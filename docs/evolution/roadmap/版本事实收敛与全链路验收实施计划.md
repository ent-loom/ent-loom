# 版本事实收敛与全链路验收实施计划

> 状态：Completed
> 最近核验：2026-09-01
> 性质：跨模块文档治理；不新增运行时能力

## 目标

将已经完成的 DDL E1-E5、Meta 静态 Adapter 与 CRUD 已稳定契约回写到公共入口，保证 README、Architecture、路线图和验收指南对同一能力给出一致结论。

本计划不重复实现 DDL、CRUD、DOC 或 UI 功能；全链路证据只复用既有 `CustomerProfile` 验收，不创建第二套示例或测试。

## 事实来源与边界

事实裁决顺序如下：

1. 已合并代码和可重复执行的测试。
2. 对应组件的 Architecture 与验收指南。
3. 领域路线图和实施清单。
4. README、领域导航及其他摘要入口。

摘要文档不能把尚未正式开放的能力写成已支持，也不能把已有代码与验收证据的能力继续写成待实现。

| 能力 | 收敛后的当前事实 | 明确边界 |
|---|---|---|
| Meta Convention | 已完成属性级裁决、项目 Convention 和 CRUD 消费闭环 | 不提前扩张公共 SPI |
| Meta Adapter | CRUD、DOC、DDL 静态 Adapter 已完成 | UI 只有公开 Contract 验收，尚无正式 Meta Adapter |
| DDL | E1-E5 已完成，覆盖 MySQL 8 建表、受控差异和 Meta 投影 | 不作为通用迁移或任意 SQL 平台 |
| CRUD | 默认 JDBC 主链和稳定 `UpdatePatch<T>` 已具备；受控 `EXISTS` 仅限服务端场景 API | 不开放 HTTP `EXISTS`、JOIN、多跳或关联投影 |

## 完成门禁

- README 与路线图不再将 Meta -> DDL、DDL E1-E5、Project Convention 或稳定 `UpdatePatch<T>` 描述为待实现。
- UI Adapter、兼容线和 CRUD 受控 `EXISTS` 的未开放边界仍被明确保留。
- 全局入口只引用一套 `CustomerProfile` 全链路证据与命令。
- 本批次完成后，后续功能主线仍需按真实调用者、验收边界和启动条件单独立项。
