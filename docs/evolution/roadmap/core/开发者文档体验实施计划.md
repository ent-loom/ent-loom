# 开发者文档体验实施计划

> 状态：Remaining
> 最近核验：2026-09-01
> 范围：面向全新项目的 ent-loom 开发者文档与后续开发工具
> 关联决策：[Docusaurus 文档展示层方案](../../decisions/core/Docusaurus文档展示层方案.md)

## 目标

面向第一次接入 ent-loom 的开发者，先完成一条真实、可复制、可验证的文档路径：

1. 确认环境和依赖。
2. 声明一个 `CustomerProfile` 实体并完成必要配置。
3. 启动应用。
4. 通过 HTTP 完成实体创建和详情查询。

首期闭环是“实体创建并查询”，不等同于完整 CRUD。完整 CRUD、机器可读契约和运行时工作台按真实需求逐步建设。

## 版本口径

- 主线开发和完整 Maven Reactor 以 JDK 21+ 为基线，快速开始按此编写。
- Core/Boot 2 的 Java 8 兼容线、Boot 3/4 的 Java 17 兼容线，按对应模块和构件单独验证。
- 本计划不改变根 POM 的 Java 约束，兼容边界以[Java 运行时与 Spring 兼容性决策](../../decisions/core/Java运行时与Spring兼容性.md)为准。

## 核心决策

1. **一个公共文档站**：Docusaurus 负责概念、指南、公共契约、示例和排障。
2. **一个权威事实源**：Architecture 维护架构不变量、HTTP 契约和错误语义；Guide 按任务组织用法，只引用契约，不复制完整参数定义。
3. **先小闭环，后增强能力**：首期先证明新项目可以跑通一条主路径，再决定是否建设实体文档接口和开发工具。
4. **首期也满足工程底线**：安全边界、版本口径、可观察信号、可重复验证和内容所有权不能因“先做小闭环”而推迟。
5. **模型职责分离**：运行态实体目录描述实体元数据；API Contract 描述 HTTP；两者不合并为万能模型。
6. **运行时工具默认关闭**：后续实体文档接口和 Workbench 必须显式启用，并具备认证授权、实体白名单和敏感字段过滤。

## 内容边界

| 内容 | 权威位置 | 首期处理方式 |
|---|---|---|
| 架构不变量、HTTP 合同、错误语义 | `docs/architecture/` | 继续维护为唯一权威来源 |
| 新项目接入、常用任务、可复制示例 | `docs/guides/` | 新增快速开始和 CRUD 调用手册 |
| 配置项和注解参考 | 对应 Component Architecture 或 Reference | 链接引用，不在 Guide 重复维护 |
| 项目实际实体、字段、枚举、关系、索引 | Entity Documentation Contract | D3 后建设 |
| 在线请求、响应、草稿和预设 | Developer Workbench | D4/D5 后建设 |

旧项目实体文档工具只作为业务无关的需求和交互参考。不得迁移其 Vue 2、业务实体、业务路径、认证方式、环境配置或旧版 CRUD 协议；任何可复用结论都必须重新对照当前代码和测试核验。

## 首期开发者路径

快速开始只覆盖以下主路径，其他能力通过“下一步”链接进入独立指南：

`JDK 21+ 与 Maven Wrapper` → `最小依赖` → `CustomerProfile 实体` → `数据源与 CRUD 配置` → `启动应用` → `CREATE` → `DETAIL`

快速开始至少包含：

- 支持版本、环境要求和 Maven Wrapper 命令。
- 最小 Maven 依赖及模块边界。
- 经过当前代码核验的 `CustomerProfile` 实体声明。
- 最小数据源、实体暴露和 CRUD Controller 配置。
- 可复制的 CREATE、DETAIL 请求和响应要点。
- 常见失败、可观察信号和下一步入口。

CRUD HTTP 调用手册继续覆盖完整任务范围：

- 查询：PAGE、LIST、FIND_ONE、DETAIL。
- 写入：CREATE、UPDATE、DELETE、SAVE_OR_UPDATE。
- 业务动作：ACTION 与 scene。
- 统计、导入导出、任务和文件等后续能力。
- 过滤、排序、分页、幂等、乐观锁和错误响应等横切主题。

每个示例说明适用场景、请求、响应要点和契约链接；完整字段定义由[CRUD HTTP 契约](../../../architecture/components/crud/HTTP契约.md)维护。

## 阶段与验收

| 阶段 | 启动条件 |
|---|---|
| D0 事实盘点 | 立即启动 |
| D1 文档最小闭环 | D0 完成示例和内容边界确认 |
| D2 文档质量门禁 | D1 主路径正文完成并能构建 |
| D3 机器可读契约 | Runtime Model 字段语义已核验，且有真实需求或独立消费者证据证明静态文档不足 |
| D4 只读 Developer Workbench | D3 契约稳定，真实新项目验证了动态实体浏览价值；形成公共 SPI 前至少有两个真实调用者 |
| D5 交互调试增强 | 只读 Workbench 已验证价值，并完成认证、授权、审计和环境隔离设计 |

### D0：事实与边界

- 核对 README、Docusaurus 首页、侧边栏、Architecture 和 Guide 的现有入口及重复内容。
- 对照当前 Java 代码和测试，区分当前能力、目标能力和旧项目参考。
- 为 `CustomerProfile` 记录源码、测试和可复用的验证证据。
- 明确 Architecture、Guide、Entity Documentation Contract 和 Workbench 的内容所有权。

验收：每类内容只有一个权威位置，旧项目行为没有被写成当前能力。

### D1：文档最小闭环

- 新增快速开始，完成首期开发者路径。
- 新增按任务组织的 CRUD HTTP 调用手册。
- 增加覆盖启动、注册、请求校验和数据库问题的最小排障内容。
- 将真实页面接入 Docusaurus 首页和侧边栏，不创建空入口。

验收：不了解框架内部实现的开发者，能在干净环境中只按快速开始完成一次 CREATE 和 DETAIL；文档站构建、链接和 Mermaid 检查通过。

### D2：示例与质量门禁

- 将实体、配置和请求映射到现有 E5 验收；缺少证据时补充最小消费者验证。
- 建立示例与当前 API 的编译或可重复核验方式，避免文档片段漂移。
- 检查示例不含业务项目名称、私有域名、Token、数据库账号或本机绝对路径。
- 由未参与实现的开发者或在干净环境中演练主路径，并记录阻塞点。
- 执行 Markdown 链接、侧边栏、Mermaid、TypeScript 和 Docusaurus 构建检查。

验收：主路径具有可重复证据，文档站构建通过，公共参数和错误定义没有多份独立维护版本。

### D3：机器可读文档契约

- 盘点 `DocEntityModel`、CRUD Runtime Model 和 Meta Descriptor 中可稳定公开的字段语义。
- 定义 Entity Documentation Contract 的版本、字段、空值和兼容性规则。
- 区分实体的静态支持能力与当前主体下的有效能力；契约不替代权限决策。
- 明确实体暴露白名单、敏感字段过滤、认证授权和默认关闭策略。
- 基于现有 Runtime Model 投影实体、字段、枚举、关系和索引，不把数据库扫描作为唯一事实源。
- 为结构快照、未知字段兼容和敏感信息不泄露增加测试。
- HTTP 能力优先使用标准 OpenAPI；只有标准无法表达时才增加有版本的 ent-loom 扩展字段。

验收：全新项目可以安全获得稳定、可版本化的实体文档 JSON；API Contract 与 Entity Documentation Contract 职责不重叠。

### D4：只读 Developer Workbench

- 实现已暴露实体的搜索，以及字段、类型、枚举、关系、索引和版本信息查看。
- Workbench 只消费 D3 契约，不在前端复制 CRUD 参数、枚举或响应结构。
- 提供到 Docusaurus 契约和指南的上下文链接。
- 默认只在开发环境启用，并验证未授权访问、实体白名单和敏感字段过滤。

验收：Workbench 能读取一个真实新项目的实体目录；关闭 Workbench 不影响 Core、CRUD、DOC 或业务应用运行。

### D5：交互调试增强

- 基于 OpenAPI 或稳定 API Contract 生成请求模板，不在前端维护第二份合同。
- 先支持只读 PAGE、LIST、FIND_ONE、DETAIL，再评估写操作。
- 写操作上线前完成环境标识、权限、审计、幂等和危险操作确认设计。
- 临时请求草稿与长期命名预设分开存储。
- 验证 Workbench 请求与普通 HTTP 调用经过相同 Gateway、治理、路由和审计主链。

验收：交互调试不产生框架旁路；前端没有复制维护实体模型和 CRUD 公共协议。

## 非目标

- 首期不迁移旧项目的 Vue 2、Element UI、登录、网关和业务实体代码。
- 首期不建设完整 OpenAPI 平台、在线调试器、代码生成器或低代码页面系统。
- 不把 Docusaurus 变成需要连接业务数据库的运行时服务。
- 不让实体文档接口绕过实体暴露、认证、权限、数据范围或敏感信息过滤。
- 不同时维护 Markdown 参数表、前端常量和 Java DTO 三份公共合同。

## 完成收口

- 将已落地能力回写 Architecture 和 Guide，路线图不代替当前事实。
- 更新 README、文档中心、领域入口、首页和侧边栏的真实链接。
- 记录 Maven 与 Docusaurus 的验证命令及结果。
- 删除重复参数表、重复示例和失效说明。
- 未启动阶段继续保留启动条件，不写成当前已支持能力。

首个较小闭环在 D1-D2 完成：全新项目开发者能够通过 Docusaurus，在干净环境中跑通一个经过验证的实体创建并查询流程，并能从任务指南进入权威契约和排障入口。
