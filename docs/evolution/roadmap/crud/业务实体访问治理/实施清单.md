# 业务实体访问治理实施清单

> 状态：R0.1 盘点中
> 最近整理：2026-10-07
> 本文只保留当前差距、执行任务和退出条件；历史测试过程见[实施记录](实施记录.md)。

## 1. 当前结论

已形成可复用的授权内核和部分 JDBC 执行闭环，但还没有完成所有 Gateway、Handler、统计、导入导出和自定义 SQL 的统一业务授权收敛。当前工作重点是整理文档和迁移边界，不是继续堆叠新的授权抽象。

已确认的原则：

- 标准请求优先使用内置 Gateway、授权 DAO、标准 JDBC 执行器和统一审计。
- 手写 Service/Handler 只负责跨实体事务、状态转换、外部副作用、复杂关系或特殊结果编排。
- 手写代码仍必须消费统一授权结果，不能自行判断权限、绕过字段能力或直接调用无作用域 DAO。
- 缺少可信上下文、授权结果或执行能力时拒绝，不回退到无范围旧路径。
- YAML、同名自动绑定和复杂关系缺省是目标语义，当前 Java SPI、注解和分类接口才是实际接入方式。

## 2. 当前能力与缺口

| 能力 | 当前状态 | 处理方式 |
| --- | --- | --- |
| 根实体 `LIST/PAGE`、详情 | 已有 JDBC 受治理闭环 | 保留内置查询执行器 |
| DAO 单目标读写 | 已有按次授权 DAO | 保留 Provider 与标准工厂 |
| DAO 批量读取 | 已有逐目标范围、字段、结果和审计 | 保留内置批量 DAO |
| DAO 批量 `UPDATE` | 已有全量原子 JDBC 执行 | 保留逐目标授权、版本和 commit 后审计 |
| Query/Command Scene | 有现有路由、幂等和场景能力 | 标准形状改用内置 Gateway，复杂动作保留 Handler |
| Stats | 有现有 Gateway 和 JDBC 执行器 | 补统一业务范围与 `STATS` 字段能力 |
| Import/Export | 有现有 Gateway、任务和文件守卫 | 补统一业务范围与字段能力 |
| 自定义 SQL | 有受限 SQL 安全和参数/投影能力 | 优先改用内置执行器；无法表达时才保留并显式适配 |
| 批量 `DELETE/INSERT`、归属变更、复杂关系、多存储 | 未形成完整闭环 | 明确拒绝，直到有独立合同和真实消费者 |

## 3. R0.1 资源与操作矩阵

矩阵是清理执行基线。每个真实消费者必须归入 `GOVERNED`、`LEGACY_ALLOWED` 或 `UNKNOWN`，并标记首选实现。新增入口先登记，再进入执行链。

| 资源/操作 | 状态 | 首选实现 | 当前入口 | 下一步结论 |
| --- | --- | --- | --- | --- |
| `MerchantOrder` 用户端/商家端 `view/PAGE` | `GOVERNED` | 内置 `AuthorizedQueryExecutor.page` | `BusinessAuthorizationService` → PAGE | 保留；不新增查询 Handler |
| `MerchantProduct` 商家 `update` 批量写入 | `GOVERNED` | 内置授权批量写入 | `openBatchWrite` → JDBC 原子事务 | 保留；不复制授权、版本和事务逻辑 |
| DAO 单目标读写 | `GOVERNED` | 内置授权 DAO | `EntityDaoAuthorizationProvider.open` | 保留；无作用域 DAO 不作为替代 |
| DAO 批量读取 | `GOVERNED` | 内置 `EntityDaoBatch` | `authorizeBatch/openBatch` | 保留；维持逐目标结果和审计 |
| Query/Command Scene Handler | `LEGACY_ALLOWED` | 标准形状改用内置 Gateway | Scene 注册器 → Router → Pipeline | 逐项判断可删除的 Handler；复杂领域动作保留 |
| Stats Gateway/Scene | `LEGACY_ALLOWED` | 内置 `StatsGateway` | `StatsGatewayImpl` → Stats Engine | 保留 Gateway，补统一业务授权 |
| Import/Export Gateway | `LEGACY_ALLOWED` | 内置 Import/Export Gateway | Pipeline + 任务/文件守卫 | 保留 Gateway，补统一业务授权 |
| DAO 自定义 SQL | `UNKNOWN` | 优先内置查询/命令/DAO | 受限 SQL 执行器 | 能消费授权结果才登记；复杂 SQL 继续拒绝 |

R0.1 退出条件：每个具体消费者都有代码入口、资源、操作、目标执行器、首选实现和测试证据；`LEGACY_ALLOWED` 不接收新增调用；`UNKNOWN` 要么登记治理，要么明确移出本轮。

## 4. 执行阶段

| 阶段 | 工作 | 退出条件 |
| --- | --- | --- |
| R0 盘点 | 完成资源/操作矩阵；区分内置实现、必要手写编排和暂不支持 | 每个消费者有明确去留和回归证据 |
| R1 合同 | 冻结资源三态、声明来源冲突、拒绝原因和内置优先规则 | 目标、当前和历史文档不再互相覆盖 |
| R2 内置迁移 | 普通查询、写入、批量、统计、导入导出优先收敛到现有 Gateway/DAO | 标准形状不再保留重复 Handler、授权或 SQL |
| R3 执行边界 | 将资源识别、能力检查和不支持拒绝放回统一入口 | 缺上下文、缺能力和未知资源均执行前拒绝 |
| R4 过渡层清理 | 已删除 `LegacyCrudAuthorizationGuard` 及空转测试；授权检查归并到 `ExecutionPipeline` | 无消费者残留；安全行为回归通过 |
| R5 文档收口 | 更新 Current、Target、Remaining 和历史索引 | 当前文档可独立说明能用什么、不能用什么 |

## 5. 本轮验收矩阵

| 维度 | 必须验证 |
| --- | --- |
| 声明 | 重复来源、未知身份/动作/字段、缺失关系拒绝；显式绑定不被同名规则覆盖 |
| 准入 | 无效凭证、伪造身份、异步隐式继承身份均拒绝 |
| 查询 | 用户/商家范围隔离；额外筛选取交集；count 与数据条件一致 |
| 单目标写入 | 目标重新授权；`WRITE` 字段、版本和影响行约束进入 SQL |
| 批量写入 | 逐目标授权；整批回滚；commit 后才记录成功审计 |
| 内置优先 | 普通请求走内置 Gateway/DAO；没有业务语义时不新增 Handler |
| 手写边界 | 下单等跨实体动作仍复用内置读取和授权，手写代码只做事务编排 |
| 拒绝边界 | 直接 DAO、未映射动作、复杂 SQL 和能力不足适配器不进入副作用 |

## 7. 暂缓项

以下能力暂不纳入当前闭环，保持执行前拒绝，不视为已支持：

- Stats 的统一业务范围与 `STATS` 字段能力。
- Import/Export 的统一业务范围、字段能力和任务授权。
- 自定义 SQL 的授权结果适配、消费者登记和复杂关联执行。
- 批量 `DELETE/INSERT`、归属变更、复杂关系和多存储事务。
- YAML 策略解析、同名绑定及默认范围/字段展开。
- 完整 workspace Reactor、真实 MySQL 和示例工程最终回归验收。
