# 策略声明与缺省约定

> 状态：Current / Target 分层
> 最近核验：2026-10-12
> Spring Boot 已支持本文的最小 YAML 合同，并与 Java、注解声明汇入现有 Core 编译和执行链。复杂关系及完整缺省诊断仍是 Target。

## 1. 三个业务概念

| 概念 | 含义 | 配置 |
| --- | --- | --- |
| 策略 | 可复用的身份、动作和范围规则 | `policies` |
| 实体绑定 | 按策略批量绑定或单实体选择，实体独立登记差异 | `policy-bindings`、`entities` |
| 关系 | 当前可信身份与实体数据的归属关联 | `relations` |

入口只声明可信来源和调用限制，不另建一套权限列表。简单身份清单由 `identities` 声明并按业务码注册；归属事实由可信 Java 解析器或显式演示模式的 `example.accounts` 核验；复杂身份使用 Java 注册扩展；入口名称和身份名称本身不生成权限。

## 2. 当前可运行的最简写法

以下配置放在 `ent.loom.crud.access` 下。前提是 Meta 已登记资源 `order`，实体的 `customerId` 类型为 `Long`，可信归属来自 Java 解析器或显式演示模式的账号绑定。

```yaml
identities:
  customer:
    id-type: LONG
policies:
  order:
    customer:
      actions: [view]
entities:
  order:
    policy: order
relations:
  customer:
    field: customerId
```

身份 `id-field` 缺省为 `customerId`；实体 `policy` 缺省为资源码 `order`；分支 `scope` 缺省为身份码 `customer`；实体字段方案优先复用资源同名方案，未登记则采用字段缺省；关系 `identity-field` 复用身份的 `id-field`。字段方案按用途登记；`RETURN` 缺省为实体普通字段，`FILTER` 缺省复用可筛选的返回字段，其他用途未声明不授权。真实双端分页及商家批量改价见 [mini-commerce 主配置](../../../../../examples/mini-commerce-spring-boot/src/main/resources/application.yml)。

## 4. 当前声明字段

| 路径 | 语义 |
| --- | --- |
| `identities.<code>.id-field` | 简单身份 ID 属性，缺省为“身份码 + Id”；不配置 Java 类名 |
| `identities.<code>.id-type` | 必填标量类型 `STRING/LONG/INTEGER/UUID`；须匹配实体关系字段类型 |
| `defaults.scope-fields` | 全局候选归属字段，仅匹配实体已有持久化字段，并禁止普通写入；不授予权限或自动添加查询条件 |
| `entities.<resource>.exclude-scope-fields` | 实体字段例外；仅声明此项不建立策略绑定，未知资源/字段拒绝 |
| `policies.<name>` | 唯一策略名称 |
| `policies.<name>.<identity>` | 已注册身份分支；未声明身份不获授权 |
| `actions` | 非空、无重复，必须在绑定实体的操作目录登记 |
| `scope` | 简单关系名称；缺省使用身份同名的已登记关系 |
| `policy-bindings.<policy>` | 非空实体资源码列表；策略和实体必须存在，列表内及跨列表重复实体拒绝 |
| `entities.<resource>.policy` | 单实体策略选择；缺省先采用批量绑定，否则资源码；显式选择与批量绑定不一致拒绝 |
| `entities.<resource>.operations.<action>` | 省略目录时按策略标准动作推导；显式非空目录整体覆盖缺省，如 `[PAGE]`、`[UPDATE]`；`[]` 仅登记业务动作，供授权 DAO 使用 |
| `entities.<resource>.fields.<identity>` | 按策略身份分支选择字段方案；缺省复用资源同名方案，否则采用字段缺省；显式方案必须存在，身份须由该策略使用 |
| `entities.<resource>.relations.<role>` | 实体关系字段例外，角色必须由该策略使用 |
| `relations.<name>.field` | 实体关系字段；缺省为“关系名 + Id” |
| `relations.<name>.identity-field` | 已核验配置身份的声明 ID 属性，或复杂 Java 快照的标量只读属性；配置身份缺省使用其 ID 字段，Java 身份缺省为“关系名 + Id” |
| `field-plans.<name>.<use>` | 字段列表，用途为 `RETURN/WRITE/FILTER/SORT/STATS/EXPAND`；字段必须在实体元数据中存在 |

Spring 属性绑定不保留空对象关系，`relations` 每项至少显式填写 `field` 或 `identity-field`。当前不支持 YAML `resolver`、自由 SQL、表达式字符串、策略继承、隐式权限并集、`deny` 优先级和 `additional-actions`；未知键及类型错误拒绝。

## 5. 缺省规则

- 认证默认 `required`；匿名和可选认证必须在入口显式声明。当前 YAML 只声明已注册身份分支。
- 简单身份清单由 YAML `identities` 声明业务码、ID 字段和类型，入口和策略统一引用业务码；复杂身份通过 Java 显式注册，具体类只校验解析结果，不作为身份选择依据。
- 实体资源码复用元数据；只对 `entities` 显式登记的实体进行同名策略选择，不自动扫描并开放其他实体。
- 多个实体复用同一策略时可通过 `policy-bindings.<policy>: [resourceA, resourceB]` 集中绑定，无需重复登记 `entities`；实体差异仍放在 `entities` 中。批量列表非空、实体不可重复；实体显式策略与批量绑定一致时仅生成一个绑定，不一致启动失败，不覆盖或合并权限。不能按类名猜测业务类别。
- `operations` 省略时，只对策略已声明的标准动作推导：`view → LIST/PAGE/FIND_ONE/DETAIL`，`create/update/delete → CREATE/UPDATE/DELETE`；不推导批量、保存或自定义业务动作。显式非空目录整体覆盖缺省，须登记策略中的每个动作；自定义动作须显式配置（如 `ship: []`）。Spring 不保留 `operations: {}`，空对象等同省略，关闭某动作的 CRUD 映射使用 `<action>: []`。
- 简单关系按当前可信身份属性解析；子账号、代理、层级等复杂关系继续由项目 Java 解析器提供。
- 缺少关系或显式引用未知字段方案时编译失败；未显式选择方案时优先复用实体资源同名方案，否则采用字段缺省，不开放动作、写入或关系展开。
- `RETURN` 未声明时允许实体元数据中的全部普通字段，不包含关系字段；显式列表覆盖缺省，`RETURN: []` 关闭返回能力，普通查询无可返回字段时拒绝执行。动态权限与实体静态上限继续收窄结果。
- `FILTER` 未声明时，默认允许 `RETURN` 中元数据允许筛选的普通字段；显式 `FILTER: [...]` 覆盖缺省，`FILTER: []` 关闭调用方筛选。身份关系范围始终强制生效，调用方筛选只能进一步收窄；`WRITE/SORT/STATS/EXPAND` 不随 `RETURN` 自动开放。
- 分页未指定排序时，框架按主键提供稳定默认排序，无需声明 `SORT: [id]`；调用方主动指定排序仍须通过 `SORT` 授权，包括主键；排序未包含主键时，框架内部追加主键保证顺序确定，不额外授予主键的返回、筛选或排序权限。

全局候选允许通过 YAML 或 `@EntCrudEntity(excludeScopeFields = "customerId")` 排除。显式 `scopeFields` 与排除冲突时拒绝；排除不会解除其他只读或不可变规则。标准元数据构建在统一冻结阶段落实这些规则，使策略静态字段上限和 DAO 使用同一份结果。

Java、注解、分类接口和 YAML 同一资源的多个显式绑定报冲突，不按装配顺序覆盖。配置在启动期冻结，不支持运行时直接修改配置对象改变授权。

## 6. 范围和字段

当前 YAML 分支授权显式登记的动作与字段方案（含 `RETURN/FILTER` 缺省），再以身份关系限制范围。项目提供 `BusinessPermissionEvaluator` 时，其拒绝有效，允许结果只能进一步收窄。最终范围为：

```text
声明式能力 ∩ 动态业务范围 ∩ 必要关系约束 ∩ 调用方筛选
```

- 空授权集合表示无数据，身份关系属性缺失、解析失败或不支持的范围拒绝执行。
- 复杂配对关系由 Java 保持元组结构，不能拆成可任意组合的集合。
- 创建由服务端填充可信归属；更新不能通过修改归属字段扩大范围。配置不代表执行器已经支持归属填充或变更。
- `fields` 是分用途的能力上限，并与实体静态上限取交集；未授予的字段不可用于返回、写入、筛选或排序。
- `STATS/EXPAND` 等用途可登记，但不代表相应执行器已完成统一业务授权闭环。

## 7. 差异和业务动作

项目优先按业务规则命名可复用策略模板，例如本人记录只读、商家数据维护、双端订单读取；实体通过 `policy-bindings` 集中绑定或 `entities.<resource>.policy` 单独选择，新增同类实体复用模板，标准操作目录采用缺省，特殊映射再显式声明。分类接口可通过 `@EntPolicy` 选择模板；重复绑定拒绝，不自动合并权限。身份名称与业务规则由项目定义。策略仅声明身份、动作和范围，不引用实体字段方案。

实体差异优先选择另一条命名明确的策略；复杂差异使用 Java 的新增、整体替换或移除合同。字段差异由 `entities.<resource>.fields.<identity>` 选择独立方案，关系差异由实体关系字段例外表达；不在字段方案中扩展动作授权。

非标准业务动作必须在操作目录显式登记，CRUD 映射不支持 `ACTION/scene`。`UPDATE` 不自动获得发货、退款、下单等能力。需要成员资格、状态判断等动态业务约束时，提供项目 evaluator 并继续消费统一授权结果。

普通查询、写入和批量优先使用框架 Gateway/DAO。跨实体事务、状态转换、外部副作用、复杂关系或特殊结果保留必要 Service/Handler。Stats、Import/Export 的统一业务范围与字段消费仍按[实施清单](实施清单.md)收敛。

## 8. 编译输出与剩余目标

当前 YAML 编译为 `EntityPolicyTemplate`、`EntityPolicyBinding`、`BusinessOperationDeclaration` 和 `CrudOperationMapping`，复用 Core 引用与冲突校验、按次授权和受约束 JDBC 执行。策略及实体绑定保留配置路径来源。

以下仍是 Target：完整展示每个值的显式、同名、项目默认及元数据来源；有效策略查看；YAML 复杂 resolver 与多关系声明；既未在 `entities` 登记也未被 `policy-bindings` 选择的自动同名绑定。没有独立合同和验收前，不把这些目标写入主配置。
