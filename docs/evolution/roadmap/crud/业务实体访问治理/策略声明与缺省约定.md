# 策略声明与缺省约定

> 状态：Current / Target 分层
> 最近核验：2026-10-12
> Spring Boot 已支持本文的最小 YAML 合同，并与 Java、注解声明汇入现有 Core 编译和执行链。复杂关系及完整缺省诊断仍是 Target。

## 1. 三个业务概念

| 概念 | 含义 | 配置 |
| --- | --- | --- |
| 策略 | 可复用的身份、动作、范围和字段规则 | `policies` |
| 实体绑定 | 实体选择策略，登记操作及实体关系差异 | `entities` |
| 关系 | 当前可信身份与实体数据的归属关联 | `relations` |

入口只声明可信来源和调用限制，不另建一套权限列表。身份清单及身份归属核验由 Java 注册；入口名称和身份名称本身不生成权限。

## 2. 当前可运行的最简写法

以下配置放在 `ent.loom.crud.access` 下。前提是 Meta 已登记资源 `order`，项目已注册可信 `customer` 身份，实体和身份均具有 `customerId` 属性。

```yaml
policies:
  order:
    customer:
      actions: [view]
entities:
  order:
    operations:
      view: [PAGE]
relations:
  customer:
    field: customerId
field-plans:
  customer:
    RETURN: [id, customerId]
    SORT: [id]
```

实体 `policy` 缺省为资源码 `order`；分支 `scope/fields` 缺省为身份码 `customer`；关系 `identity-field` 缺省为 `customerId`。字段方案按用途显式登记，未声明用途不授权。真实双端分页及商家批量改价见 [mini-commerce 主配置](../../../../../examples/mini-commerce-spring-boot/src/main/resources/application.yml)。

## 4. 当前声明字段

| 路径 | 语义 |
| --- | --- |
| `defaults.scope-fields` | 全局候选归属字段，仅匹配实体已有持久化字段，并禁止普通写入；不授予权限或自动添加查询条件 |
| `entities.<resource>.exclude-scope-fields` | 实体字段例外；仅声明此项不建立策略绑定，未知资源/字段拒绝 |
| `policies.<name>` | 唯一策略名称 |
| `policies.<name>.<identity>` | 已注册身份分支；未声明身份不获授权 |
| `actions` | 非空、无重复，必须在绑定实体的操作目录登记 |
| `scope` | 简单关系名称；缺省使用身份同名的已登记关系 |
| `fields` | 字段方案名称；缺省使用身份同名的已登记方案 |
| `entities.<resource>.policy` | 策略选择；缺省为资源码，资源和策略都必须存在 |
| `entities.<resource>.operations.<action>` | 动作目录及 CRUD 形状列表，如 `[PAGE]`、`[UPDATE]`；`[]` 仅登记业务动作，供授权 DAO 使用 |
| `entities.<resource>.relations.<role>` | 实体关系字段例外，角色必须由该策略使用 |
| `relations.<name>.field` | 实体关系字段；缺省为“关系名 + Id” |
| `relations.<name>.identity-field` | 已核验身份的 record 属性或 JavaBean getter；缺省为“关系名 + Id”，必须是字符串、数字或 UUID 属性 |
| `field-plans.<name>.<use>` | 字段列表，用途为 `RETURN/WRITE/FILTER/SORT/STATS/EXPAND`；字段必须在实体元数据中存在 |

Spring 属性绑定不保留空对象关系，`relations` 每项至少显式填写 `field` 或 `identity-field`。当前不支持 YAML `resolver`、自由 SQL、表达式字符串、策略继承、隐式权限并集、`deny` 优先级和 `additional-actions`；未知键及类型错误拒绝。

## 5. 缺省规则

- 认证默认 `required`；匿名和可选认证必须在入口显式声明。当前 YAML 只声明已注册身份分支。
- 身份清单由 Java 注册，不重复写入 YAML。
- 实体资源码复用元数据；只对 `entities` 显式登记的实体进行同名策略选择，不自动扫描并开放其他实体。
- 多个实体复用同一策略时显式选择，不能按类名猜测业务类别。
- 简单关系按当前可信身份属性解析；子账号、代理、层级等复杂关系继续由项目 Java 解析器提供。
- 缺少关系或字段方案时编译失败，不变成全量授权。

全局候选允许通过 YAML 或 `@EntCrudEntity(excludeScopeFields = "customerId")` 排除。显式 `scopeFields` 与排除冲突时拒绝；排除不会解除其他只读或不可变规则。标准元数据构建在统一冻结阶段落实这些规则，使策略静态字段上限和 DAO 使用同一份结果。

Java、注解、分类接口和 YAML 同一资源的多个显式绑定报冲突，不按装配顺序覆盖。配置在启动期冻结，不支持运行时直接修改配置对象改变授权。

## 6. 范围和字段

当前 YAML 分支授权显式登记的动作与字段用途，再以身份关系限制范围。项目提供 `BusinessPermissionEvaluator` 时，其拒绝有效，允许结果只能进一步收窄。最终范围为：

```text
声明式能力 ∩ 动态业务范围 ∩ 必要关系约束 ∩ 调用方筛选
```

- 空授权集合表示无数据，身份关系属性缺失、解析失败或不支持的范围拒绝执行。
- 复杂配对关系由 Java 保持元组结构，不能拆成可任意组合的集合。
- 创建由服务端填充可信归属；更新不能通过修改归属字段扩大范围。配置不代表执行器已经支持归属填充或变更。
- `fields` 是分用途的能力上限，并与实体静态上限取交集；未授予的字段不可用于返回、写入、筛选或排序。
- `STATS/EXPAND` 等用途可登记，但不代表相应执行器已完成统一业务授权闭环。

## 7. 差异和业务动作

实体差异优先选择另一条命名明确的策略；复杂差异使用 Java 的新增、整体替换或移除合同。当前 YAML 只提供实体关系字段例外，不建立第二套局部策略覆盖语法。

业务动作必须在操作目录显式登记，CRUD 映射不支持 `ACTION/scene`。`UPDATE` 不自动获得发货、退款、下单等能力。需要成员资格、状态判断等动态业务约束时，提供项目 evaluator 并继续消费统一授权结果。

普通查询、写入和批量优先使用框架 Gateway/DAO。跨实体事务、状态转换、外部副作用、复杂关系或特殊结果保留必要 Service/Handler。Stats、Import/Export 的统一业务范围与字段消费仍按[实施清单](实施清单.md)收敛。

## 8. 编译输出与剩余目标

当前 YAML 编译为 `EntityPolicyTemplate`、`EntityPolicyBinding`、`BusinessOperationDeclaration` 和 `CrudOperationMapping`，复用 Core 引用与冲突校验、按次授权和受约束 JDBC 执行。策略及实体绑定保留配置路径来源。

以下仍是 Target：完整展示每个值的显式、同名、项目默认及元数据来源；有效策略查看；YAML 复杂 resolver 与多关系声明；不经显式 `entities` 登记的同名绑定。没有独立合同和验收前，不把这些目标写入主配置。
