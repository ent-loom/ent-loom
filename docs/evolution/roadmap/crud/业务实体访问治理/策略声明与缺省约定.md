# 策略声明与缺省约定

> 本文保留历史背景，实体文件语法已废止；现行实体声明见[配置参考](../../../../guides/配置参考.md#实体注解)。

全局 `ent.loom.crud.access` 声明 identities、relations、default-policy、defaults 与 policies；实体级策略与字段差异使用 Java 注解。

- actions 省略继承策略，列表整体替换（[] 关闭全部），实体对象支持 add/remove 且 remove 优先；全局策略保持完整列表，动作不支持 *；grants 按全局默认 → 策略 → 实体逐层处理，列表替换、空列表撤权、add/remove 增减，remove 优先；* 展开实体最终动作。
- scopes 按身份覆盖，缺失范围拒绝；公共访问要求实体显式范围或 rules 和 RETURN INCLUDE 白名单。rules 使用简单字段等值/集合条件，不在 YAML 中引入复杂条件语言。
- operations 省略动作沿用标准缺省，非空列表替换，空列表关闭通用入口、保留同名业务 Handler；不允许跨动作混入单条或批量映射。
- 当前接入查询、单条 CRUD、批量 UPDATE 与显式业务 ACTION；批量逐目标授权、校验版本并整批回滚，其他未接入动作开放即启动失败。
- 字段采用 INCLUDE/EXCLUDE/ALL/NONE，默认 EXCLUDE；INCLUDE 必须非空，ALL/NONE 不带字段，未知字段和重复用途拒绝。
- ownership 省略按共享关系与已有标量字段推导，显式列表整体替换，空列表关闭推导；底层范围约束仍保留。
- HTTP 发布与策略继承独立：有 crud 对象声明且未关闭才发布，无声明不自动发布；已发布实体必须选择策略或继承 default-policy，并完成实际编译。
- Java EntityPolicyTemplate 仍通过 crud.access.policy 选择；YAML/Java 策略重名、文件与程序重复绑定同一实体均拒绝。
- 业务动作不退回旧主体授权；Handler 通过 AuthorizedActionContext 获取可信身份与范围，根实体约束进入实际 SQL，关联实体通过固定业务关系访问。
- ConfiguredAccessPolicies.snapshot() 提供服务端有效配置与来源诊断，不自动发布公共接口。

完整语法见[配置参考](../../../../guides/配置参考.md#实体注解)，方案与验收边界见[全局策略与实体定制](全局策略与实体定制.md)。

公共分支的 EXPAND 默认 NONE；显式开放仅支持 INCLUDE，并须逐个列出 `customer.id` 这样的关联字段，不能用 ALL、EXCLUDE 或只列关联名称开放整段数据。

业务 Handler 的 `relatedAccess()` 默认空列表；关联 DAO 须声明目标实体、允许操作与范围字段。下单只读 Customer.id、MerchantProduct.id，只向 OrderItem.orderId 范围新增明细；调用时必须绑定声明字段的非空等值或 IN 条件，无限制范围、未声明实体及其他操作均拒绝。根实体仍自动叠加本次授权范围。

业务动作审计绑定最终事务完成通知：加入外层事务时等待最终提交或回滚，只记录一次结果；审计写入异常单独记录日志，不将已提交的业务改为失败。自定义事务执行器须实现 executeObserved，否则明确拒绝业务动作。
