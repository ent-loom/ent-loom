# 策略声明与缺省约定

> 状态：Target
> 最近整理：2026-10-07
> 本文是目标声明合同。当前实际接入仍以 Java SPI、注解和分类接口为准；YAML 解析器尚未作为可用 API 发布。

## 1. 只保留三个概念

| 概念 | 含义 | 示例 |
| --- | --- | --- |
| 策略 | 可复用的身份、动作、范围和字段规则 | `order` |
| 身份分支 | 某种业务身份在策略下可执行的动作 | `merchant` |
| 实体绑定 | 实体选择策略及关系/字段差异 | `orderMain -> order` |

入口只声明可信来源和调用限制，不另建一套权限列表。入口名称本身不授予业务权限。

## 2. 目标最简写法

```yaml
policies:
  order:
    customer:
      actions: [view, place, cancel]
    merchant:
      actions: [view, ship]

entities:
  orderMain:
    policy: order
```

这段配置只表达策略和实体选择。身份清单、默认范围、字段方案和动作目录由项目一次注册，不能仅凭身份名称自动生成权限。

## 3. 当前与目标

| 能力 | 当前口径 |
| --- | --- |
| Java 策略模板、身份分支、实体绑定、显式差异 | 已有实现 |
| 注解、分类接口和 Java Bean 汇入统一注册 | 已有实现 |
| 未知身份、动作、字段、关系和冲突拒绝 | 已有静态编译合同 |
| YAML 解析、严格 schema、同名绑定、默认展开 | Target |
| 商家子账号、代理合作和共享资源完整方案 | 业务扩展目标，不是 Core 默认能力 |

## 4. 声明字段

| 路径 | 语义 |
| --- | --- |
| `policies.<name>` | 唯一策略名称 |
| `policies.<name>.<identity>` | 已注册身份分支；未声明身份不获授权 |
| `actions` | 非空、无重复、已在资源操作目录注册的动作 |
| `scope` | 已注册范围方案；缺省时使用项目为身份/资源注册的安全默认 |
| `fields` | 已注册字段方案，分别表达 `RETURN/WRITE/FILTER/SORT/STATS/EXPAND` |
| `entities.<resource>.policy` | 策略选择；未知策略编译失败 |
| `relations.<name>.field` | 简单关系的实体属性；省略时使用约定同名属性 |
| `relations.<name>.identity-field` | 简单关系的身份属性；省略时使用关系默认属性 |
| `relations.<name>.resolver` | 复杂关系解析器 code，与字段映射互斥 |

本版不提供自由 SQL、表达式字符串、策略继承、隐式权限并集、`deny` 优先级和 `additional-actions`。未知键、重复键和类型错误都必须报错。

## 5. 缺省规则

- 认证默认 `required`；匿名和可选认证必须在入口显式声明。
- 身份清单由 Java 注册，不重复写入 YAML。
- 实体资源码复用实体元数据；不在 YAML 发明第二套命名规则。
- 显式策略绑定优先；没有显式绑定时，只有已登记资源才允许同名策略推导。
- 多个实体复用同一策略时必须显式选择，不能按类名猜测业务类别。
- 简单关系可以按约定字段推导；商家子账号、代理合作、层级关系必须由项目范围方案或解析器明确提供。
- 没有安全默认范围或字段方案时编译失败，不变成全量授权。

显式来源包括 Java、注解、分类接口和未来 YAML。同一资源存在多个显式来源时报冲突，不按装配顺序覆盖；同名推导只在没有显式来源时生效。

## 6. 范围和字段

范围方案决定如何组合当前身份、业务操作、成员资格和关系事实；关系解析器只提供事实。最终范围为：

```text
策略范围 ∩ 动态业务范围 ∩ 必要关系约束 ∩ 调用方筛选
```

- 空授权集合表示无数据，解析失败或不支持的范围拒绝执行。
- 配对关系保持元组结构；不能把 `(商家A, 店铺A)` 与 `(商家B, 店铺B)` 拆成可任意组合的集合。
- 创建由服务端填充可信归属；更新不能通过修改归属字段扩大范围。
- `fields` 不是普通字段列表。未授予的用途和字段不可使用，并与实体静态上限取交集。

## 7. 差异和业务动作

实体差异优先选择另一条命名明确的策略；复杂差异使用 Java 的新增、整体替换或移除合同。本版 YAML 不建立第二套局部覆盖语法。

业务动作必须在操作目录中显式注册并映射到 CRUD/scene。`UPDATE` 不自动获得发货、退款、下单等能力。策略声明只是静态能力上限，最终仍要经过动态权限、关系、状态、字段和执行能力校验。

普通查询、写入、批量、统计和导入导出优先使用框架内置 Gateway/DAO。只有跨实体事务、状态转换、外部副作用、复杂关系或特殊结果才保留手写 Service/Handler。

## 8. 编译输出

编译器必须冻结有效策略并保留每个值的来源：显式声明、同名推导、项目默认或实体静态元数据。至少能诊断：

- 未知策略、身份、动作、字段和关系；
- Java/注解/YAML 重复来源；
- 缺少默认范围或字段方案；
- 复杂关系缺少解析器；
- 资源未登记或执行器不支持授权约束。

“有效策略查看”应显示资源、策略来源、身份、动作、范围、字段方案和缺省来源。没有解析器和验收证据前，不得把本文 YAML 示例复制到 `application.yml` 当作已支持配置。
