# 策略声明与缺省约定

现行实现采用 Java 业务授权与实体静态边界：

- `identities` 配置仅声明简单身份结构，运行配置不承载授权规则。
- 实体 `policy` 选择 Java 模板，或由 Java `EntityPolicyBinding` 绑定，两者不能重复。
- 实体 `actions` 默认只有 `view`，空集合关闭全部动作，列表完整表达操作上限。
- 标准动作自动生成操作目录与映射；未接入的形状明确拒绝，不跨动作映射。
- `fieldLimits` 按 RETURN、WRITE、FILTER、SORT、STATS、EXPAND 区分，未列出的用途关闭。
- `BusinessPermissionEvaluator` 每次返回范围与字段能力，缺失或空决策默认拒绝；只能收窄静态上限。
- 关系复用 `@EntRelation`，Java 策略显式选择，归属保护使用 `scopeFields`，身份结构不推导实体字段。
- HTTP 暴露与权限独立；内部未绑定实体不自动发布、不自动授予权限。
- Java 模板重名、绑定冲突、越过动作上限在启动期失败。
- 业务动作与 MVC 复用同一按次授权；原始 Mapper 负责实际落实约束，写入审计等待最终事务完成。

最小示例见 [customer-profile](../../../../../examples/customer-profile-spring-boot/src/main/java/com/example/customerprofile/ProfileAccessConfiguration.java)，商城组合示例见 [application.yml](../../../../../examples/mini-commerce-spring-boot/src/main/resources/application.yml)。
