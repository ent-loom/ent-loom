## 当前结论

- 普通请求优先走内置 Gateway、授权 DAO、标准 JDBC 执行器和统一审计。
- 只有跨实体事务、状态转换、外部副作用、复杂关系或标准执行器无法表达的结果，才保留手写 Service/Handler。
- 授权结果必须真正进入查询、写入、字段投影和事务边界；只有入口授权而没有执行约束不算完成。
- 缺少可信上下文、授权结果或执行能力时拒绝，不回退到无范围的旧路径。
- YAML、同名自动绑定和复杂关系缺省目前是目标语义，不代表当前可直接配置。

## 当前支持边界

| 能力 | 当前口径 |
| --- | --- |
| 根实体列表、分页、详情 | JDBC 已有受治理闭环，范围与字段能力进入执行 |
| DAO 单目标读写 | 已有按次授权 DAO 和标准 JDBC 执行 |
| DAO 批量读取 | 已有逐目标范围、字段、结果和审计 |
| DAO 批量 `UPDATE` | 已有全量原子 JDBC 执行和 commit 后审计 |
| Query/Command Scene | 有现有路由、幂等和场景能力，统一业务授权仍按消费者收敛 |
| Stats、Import、Export | 有现有 Gateway 和执行管线，统一业务范围/字段消费仍在清理范围 |
| 自定义 SQL、复杂关联、多存储 | 只有显式适配且能消费授权约束时才支持，否则拒绝 |

详细测试命令和结果见[实施清单](实施清单.md)及[实施记录](实施记录.md)。
