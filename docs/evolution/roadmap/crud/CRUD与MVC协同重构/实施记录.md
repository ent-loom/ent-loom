## 当前进度

- 标准 HTTP 分页默认 1 页、20 条，单页上限 100；详情支持独立目标 ID，并拒绝混合筛选及非唯一主键条件。相关提交 `63c50b21`、`0f2acbb6`。
- 详情 HTTP 只接受顶层 `id`，缺失、非标量及旧筛选目标均拒绝；调用方、示例和当前指南已迁移。
- 修复服务端错误响应泄露异常消息、SQL 及内部路由的问题，提交 `15e43293`。
- 修正 mini-commerce 客户、商家、商品及订单明细的范围声明和 H2 测试结构，提交 `fa7dafe8`。
- 商品摘要 MVC 与标准 CRUD 使用同一 `merchantProduct/view` 授权服务；每次调用独立授权，固定 DTO 投影，支持 `ALL`、`NONE` 和可信商家 ID 等值范围。原始 JDBC Mapper 由业务落实授权范围、字段和参数绑定，无法表达的范围在 SQL 前拒绝。查询和 count 使用相同条件。
- 受授权分页的显式排序、默认排序和稳定主键排序均校验本次 `SORT`，缺少能力时在 SQL 前拒绝；字段可用于排序不代表可返回。
- 动态授权区分操作拒绝与目标不可访问；无目标时后者按操作拒绝处理。标准详情和单目标写入分别返回与 SQL 未命中一致的 404 和 409，审计保留拒绝类别，声明式配置不会丢失动态判定。
- 核心实体绑定及实体 YAML 支持显式字段上限，未声明用途关闭，超出元数据上限的字段在启动时拒绝，动态授权和诊断快照均受其约束；注册分页映射时必须在静态上限开放主键排序。商城商品已声明首期返回、筛选、排序和写入上限，归属字段筛选测试已迁移为拒绝。

## qyw 资源合同推演

以本机 `qingyiwei/qyw/business-center` 的 `BusMoralRecordLine` 为实例：实体声明 `moral` 入口，并持有 `schoolId`、`classId`、`studentId`；它是点评明细而非跨班批次头。证据为 `v2/moral/entity/BusMoralRecordLine.java`、`v2/platform/governance/GovernanceAccessEntryResolver.java`、`v2/platform/scope/ScopeResolver.java`、`v2/platform/scope/impl/TeacherScopeProvider.java`、`ParentScopeProvider.java` 和 `v2/platform/loom/BusinessV2CrudDataScopeResolver.java`。此处是合同推演，不声称 qyw 已迁移到 2.0。

| 场景 | 授权结果的目标表达 | 必要约束 |
| --- | --- | --- |
| 已校验学校，校内全量获明确授权 | `schoolId = S` | 全校不是跨学校 `ALL`；请求选择的学校须先校验 |
| 教师按班级授权 | `schoolId = S AND classId IN C` | `C` 由可信关系事实产生，普通请求筛选只能继续收窄 |
| 家长按学生授权 | `schoolId = S AND studentId IN P` | `P` 来自家长与学生关系，不能由请求提交代替 |
| 同时要求班级与学生边界 | `schoolId = S AND classId IN C AND studentId IN P` | 两者是独立安全边界时取交集；若业务定义为替代授权，须显式声明 `OR`，不能推断 |

例如 `C={10,11}`、`P={101,102}` 时，最终谓词限定学校 S、班级 10 或 11、学生 101 或 102 三者交集；额外请求 `classId=12` 只能令结果为空。`AuthorizationScope` 的 `EQUAL/IN/AND/OR` 可以表示这些同表条件，但当前可信上下文尚无经过校验的学校选择合同，不能把 `filter` 中的学校直接当授权事实。`NONE` 明确表示允许但无记录；无法确认入口、学校归属或集合关系时拒绝，空集合不可解释为 `ALL`。

qyw 现有转换逻辑在教师同时有班级和学生集合时优先班级分支，并非自动对两者取交集；是否需要更严格交集取决于具体业务规则。批次头跨班时 `classId` 可为空，不能直接把明细的行级条件套用到批次头；多表、历史归属、毕业范围及原始 Mapper 需要独立授权规则和可验证的 SQL，首期无法落实时在执行前拒绝，不回退全量或旧链。
