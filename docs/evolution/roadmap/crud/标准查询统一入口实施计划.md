# 标准查询统一入口实施计划

> 状态：当前示例的标准读取与一级关联迁移已完成；可信下单与强类型结果按需求推进。日期：2026-10-16。

## 目标与边界

标准读取零业务 Controller，实体声明与身份字段方案承载范围和公开契约。通用 HTTP 是适配层，实体和业务操作是授权边界；客户端只能访问服务端声明的实体、字段、关系和操作，不开放任意 SQL 或任意连接。

本轮小闭环以当前订单列表、详情和下单不回归为边界。业务动作使用既有显式场景授权，未顺带重写下单聚合创建授权；不将读取收口表述为所有业务动作均已迁入新策略。

## 第一步：普通根实体通用读取（已完成）

- 内置 `EntCrudQueryController` 按实际 Handler、暴露实体及策略绑定识别新授权资源，别名与自定义 base-path 使用同一准入。
- 默认 REQUIRED 准入，复用可信认证、身份核验及访问者作用域；缺失来源、缺失或无效凭证拒绝。
- 四种读取复用 Gateway → 授权 → JDBC → 白名单投影 → 审计，不调用旧主体解析器或演示 grants；未绑定资源保留原有治理。
- 商品、文章、地址和订单均使用通用查询。列表 `data.items`，分页 `data.items/data.page`，单条 `data.item`；请求统一使用 `options`。

## 第二步：订单读取与显式业务动作共存（已完成）

- 标准操作继续按资源策略授权；实体显式声明且没有新策略 ACTION 映射的业务动作，明确走场景的入口、能力、主体、事务和审计链。新映射优先；未知动作不能凭 Handler 存在而获准，可信作用域始终禁止降级，不捕获授权失败后回退。
- `Order` 选择全局 `order-read`；客户与商家查询同一 `order` 资源，范围只来自可信身份，对侧 ID 只能收窄筛选。
- 删除两个查询 Controller、两个分页 DTO、OrderQueryService 与局部 OrderQueryConfiguration；旧两条业务查询路径删除。
- 下单保留 `place` 场景授权及 EntityDao 业务实现，验证拆单、成交快照、归属保护、第二个商家保存失败的整批回滚。普通订单写入继续拒绝。

## 第三步：受限一级关联投影（已完成）

- `EXPAND` 复用现有身份字段方案，支持本地一级关系和「关系.普通字段」白名单，启动期依据同一元数据关系图检查路径。
- 根记录消费身份授权范围；关联消费父资源的 EXPAND 授权，并仅按实际授权根记录的连接键读取。根分页和 count 与关联补数分离，关联逻辑删除仍生效。
- 明细在授权订单内读取，关闭独立 HTTP 不妨碍聚合读取，也不授予独立访问权限。客户邮箱仅客户自己可见，商家只读客户 ID 与名称。
- 补数按 200 个键一批，每个关系单次最多 1000 条，超限和单值关系不唯一明确失败。内部连接键不自动进入响应，成功审计在全部补数和投影完成后记录。
- 实体/DTO、查询场景、多实体连接、关系筛选、嵌套及远程关联仍拒绝。目标资源另行授权的关系应使用专门业务能力，不配置为父资源直接可展开关系。

使用方式见[双端分页入口与范围](../../../guides/crud/双端分页入口与范围.md)和[受授权关联读取](../../../guides/crud/受授权关联读取.md)。

## 后续：可信下单与按需查询扩展

- 下单从可信客户身份确定归属，显式授权商品读取及订单聚合创建，替代当前演示场景的结算对象 customerId；该项需要独立业务闭环。
- 固定组合查询通过声明式查询/Query Handler 扩展，复用授权、分页、审计；跨系统协议按需保留自定义 Controller。
- 强类型结果独立适配，明确字段缺失、null、枚举/日期和序列化规则，不绕过投影白名单。
- 任意多实体连接、复杂聚合与通用报表引擎不作为本次迁移目标。

JDK 21 完整 ent-loom Maven Reactor 测试共 1104 项，无失败，4 项专用 MySQL 集成测试按默认条件跳过；mini-commerce 共 82 项，无失败，3 项专用 MySQL 表结构检查默认跳过。验证覆盖分页与 count、缺失凭证、跨归属详情、筛选交集、无计数分页、关联字段差异、隐藏连接字段、逻辑删除、规模限制、旧主体不再授权读取、下单快照与整批回滚。真实数据库验收证据维护在[MySQL 8 验收](https://github.com/ent-loom/ent-loom/blob/main/examples/mini-commerce-spring-boot/docs/mysql-acceptance.md)。
