# 实体必填约束与统一校验

> 状态：Accepted，创建最小闭环已实施
> 决策日期：2026-09-19
> 范围：Meta、CRUD、Doc/UI；普通实体 CRUD

## 业务原则

普通 CRUD 业务只表达“字段是否必填”，无需区分 `NotNull`、`NotBlank`、`NotEmpty`。以实体 `required` 为业务字段必填约束，由 CRUD 统一校验，Doc/UI 投影展示；错误文案默认使用字段 label。

本决策升级原有“required 仅为输入提示”的语义。普通创建链的最小闭环已完成；更新显式清空和结构化错误仍按本文后续范围演进。

## 类型与默认策略

| 字段类型 | required 为 true 时的有效值 |
|---|---|
| 字符串 | 非 null，且不能全为空白 |
| 数组、集合、Map | 非 null，且至少有一个元素或条目 |
| 数值、布尔、枚举及其他对象 | 非 null；0、false 合法 |

集合元素、嵌套对象、数值范围、格式、跨字段业务不变量另行约束；required 不递归替代这些校验，也不补零、空字符串或首个枚举值。

- 字段 `TRUE` 明确必填，`FALSE` 明确可选，`UNSET` 表示未声明；未声明时可由 Validation 默认组提供补充推断，否则保持未知。
- Java 类型只决定“如何校验”，不决定“是否必填”。必填语义贴近字段声明，避免实体级默认规则造成隐式约束。
- 系统生成、治理注入、只读等字段按明确元数据识别，不根据类型或宽松名称猜测生成行为。

## 项目级必填推断

框架提供可选的 `RequiredInferenceFilter` 扩展点，由项目决定是否启用默认推断；框架核心不写死具体业务规则。过滤器接收实体、字段和创建上下文，返回 `TRUE`、`FALSE` 或 `UNSET`，并保留推断来源与原因。

推荐的保守策略是：生成/只读字段创建时不必填，字符串默认可选，其他可写字段默认必填；字段显式 `required` 优先覆盖推断。裁决顺序为：显式字段规则 > 生成/只读规则 > 项目过滤器 > 未声明。

该策略用于减少常规字段上的重复声明，不能替代业务例外，也不根据字段名或 Java 类型名称猜测业务含义。项目应通过启动诊断或运行时模型检查验证推断结果；过滤器属于项目约定，不作为所有项目的全局默认。

## 必填、赋值与展示分离

业务字段必须有值，不等于请求必须显式提供值。`required` 与默认值、只读、自动生成属性独立；有默认值或系统赋值不能直接把业务约束改成 false。运行时同时投影 `inputRequired`，表示客户端创建请求是否必须显式输入，推断规则为 `required && writable && 无默认值`，数据库生成主键另行豁免。

创建时先完成默认值补齐、治理注入和业务准备，再在业务写入前校验。默认值只补缺失 key/字段，显式 `null` 保留并由 required 校验决定结果。由业务处理器计算的字段在计算完成后检查；数据库生成主键排除插入前检查，在生成结果边界检查。阶段豁免依据生成策略，不永久取消约束。

Doc/UI 可以按操作场景调整输入提示，例如生成字段无需用户输入，但展示覆盖不得改变服务端业务约束。DDL 可空性仍独立，不能从 required 直接推导数据库 NOT NULL；required 也不保证每个响应都投影该字段。

## CRUD 执行边界与错误信息

- 在 CRUD 公共写入链提供统一校验能力；Core 消费 CRUD Runtime Model，Adapter 只投影元数据，不执行校验。
- 默认创建、强类型 Handler、导入及批量写入复用规则，不能只在 HTTP Controller 校验。
- `AbstractEntityCreateHandler` / `CrudCreateHandler` 是接入点之一，不能仅覆盖继承这些模板的路径。复杂业务场景保留显式校验阶段，直接 DAO 调用不假定自动获得场景校验。
- 创建最终校验 `required=true` 字段；`writable=false` 的系统字段、应用生成字段需要在业务准备阶段或专门生成策略完成后补齐，不能把 `inputRequired=false` 理解为业务可为空。
- 强类型创建处理器通过 `prepareCreateEntity` 承接业务计算、治理补充和默认值准备；Map/CrudRecord 请求保留原始字段集合，以区分 primitive 的未传入与显式 `false/0`。
- 局部更新区分“未传字段”与“显式清空”：未传不按创建规则检查，显式清空必填字段应拒绝。反序列化为实体前保留字段存在性，基本类型的零值不能证明请求提供过字段。
- 文案优先级：业务自定义文案 > `label + 约束文案` > 字段名兜底；普通必填错误默认“商品名称不能为空”。结构化错误保留字段路径和错误码，批量场景带记录位置。

## Validation 的位置

普通 CRUD 实体不再强制使用 `@NotNull/@NotBlank/@NotEmpty`；复杂 DTO 可按需保留 Bean Validation。现有注解推断作为可选接入能力，不再作为实体必填的主要依据；字段显式规则优先，Validation 仅在未声明时提供补充依据。

`required = FALSE` 仅覆盖框架自身的必填规则，不会禁用独立 Bean Validation 引擎的 `@NotNull`。迁移时清理同一字段的重复或冲突声明，避免两套校验重复报错。

## 当前实现与迁移

当前已实现：

- 字段显式必填/可选规则及 Validation 默认组兼容推断；默认值、只读、生成策略不再直接把 required 降为 false。
- `required + label` 投影到 CRUD Runtime Model。
- `createDefaultValue` 投影到 CRUD Runtime Model/EntityMeta；强类型创建、默认 JDBC CREATE、DAO CREATE 统一补齐缺失默认值，显式 `null` 不替换。
- `inputRequired` 与 `required` 分离，生成主键、只读字段和有默认值字段不要求客户端显式输入。
- 字符串、数组、集合、Map 和其他对象的创建校验；0、false 合法。
- 强类型创建 Handler、默认 JDBC CREATE、DAO 命令 CREATE，以及由 CREATE 子命令执行的批量创建。
- 数据库生成主键的插入前豁免；商城 Customer/Product 已移除重复 Validation 注解。

尚未完成：局部更新显式清空校验、结构化字段错误及独立导入错误定位。直接调用底层 EntityDao 不自动获得场景校验。后续范围见 [Meta 路线图](../../roadmap/meta/index.md)。
