# 关系映射自动补全与显式加载

> 状态：Accepted
> 日期：2026-10-20
> 范围：Meta 关系事实到 CRUD 展开映射，Meta-first 与 CRUD-only 共用

## 决策

**关系事实单处声明，唯一映射自动补全，加载与授权显式选择，歧义才补配置。**

```java
// OrderItem：关系事实。
@EntRelation(targetEntity = "order")
private Long orderId;

// Order：无需重复声明关系目标、外键、基数或空的组件标记。
@EntField("订单明细")
private List<OrderItem> orderItemList;
```

Meta 只描述通用事实。CRUD 在统一运行时模型构建阶段，结合已注册实体、可解析集合泛型和唯一反向 `MANY_TO_ONE` 关系，补全本地 `ONE_TO_MANY` 映射。保留实际连接键，不假设目标字段一定是 `id`；已有同名显式映射优先。单对象继续按已声明外键的 `xxxId → xxx` 名称及目标类型绑定，不凭对象类型猜测引用。

省略字段上的关系注解不再禁止生成候选展开映射；默认弱关系表示没有自动加载和生命周期耦合。普通 DAO 与未请求展开的通用查询仍只读当前实体，`expandRelations` 选择本次加载，HTTP 还必须取得父资源的 `EXPAND` 字段授权。

声明式访问策略在操作与身份授权成立后，省略 `EXPAND` 时按 `EXCLUDE: []` 开放已解析关系的候选普通字段，无需重复配置能力开关；`NONE` 关闭，`INCLUDE/EXCLUDE` 声明字段差异。映射补全本身不授予权限；Core 的 Java 自定义授权仍由项目显式返回字段能力，动态拒绝与交集不被缺省覆盖。

## 边界

- 没有关系事实、目标实体未注册、集合泛型未知、临时集合或反向候选不唯一时，不生成集合映射。歧义由 `@EntCrudField` 等显式配置消除；未解决的展开配置或请求必须拒绝。
- 不根据字段名创造外键关系；不反推一对一唯一性、多对多、远程关系或业务过滤集合。
- 显式同名映射优先；推导结果携带 `crud.relation.collection.unique-reverse` 来源，模型合并后重新裁定，避免扫描顺序决定结果。
- 推导只消费组件关系模型，不让 CRUD Core 依赖 Meta Core，不回写 Meta Descriptor，不改变 DDL 外键或 DOC/UI 语义。
- 不自动开启加载、级联写入、级联删除或访问权限。关联读取仍遵循分页、投影、逻辑删除及单次关联条数上限。

## 被替代规则与验证

替代[核心契约](../../../architecture/core/元数据约定与裁决契约.md#21-实体关系与结构属性默认弱关系)中“没有显式装配声明就禁止绑定结构属性”的旧约束；同步核心思想、Meta 指南、运行时适配器说明和商城示例。

验证覆盖 CRUD-only、Meta-enabled、继承属性、非主键连接、扫描顺序、无事实、歧义、显式优先、泛型未知及模型重新合并。商城通过现有通用 HTTP 消费者验证默认不展开、显式展开、父订单归属、关联字段投影、分页与成交快照。
