# 能力操作重构决策

> 状态：Accepted
> 当前事实：[Query/Command 协议与路由](../../../architecture/components/crud/查询命令协议.md)

该决策已落地到当前 CRUD 契约；实现状态和验收证据以当前架构文档及其测试为准。

## 背景

旧模型同时用 capability 表达框架操作分类和业务权限码，并把 Stats 混入 Query operation，导致 HTTP、路由、治理、审计和 Engine 能力声明无法使用同一结构。

## 决策

框架操作统一表示为：

```text
CrudOperationDomain + scoped operation enum -> CrudOperationKey
```

当前操作域：

| Domain | Operation |
|---|---|
| QUERY | PAGE、LIST、FIND_ONE、DETAIL |
| COMMAND | CREATE、UPDATE、DELETE、SAVE_OR_UPDATE、Batch、ACTION |
| STATS | QUERY、PREVIEW |
| IMPORT | VALIDATE、SUBMIT、COMMIT、CANCEL、STATUS、DOWNLOAD_ERROR |
| EXPORT | SUBMIT、DOWNLOAD、STATUS、CANCEL、PREVIEW |

`capability` 只表示业务权限码，不再作为框架操作分类。合法组合由 `CrudOperationMatrix` 校验，禁止任意字符串组合。

## 统一使用点

- Spec 使用 `CrudOperationKey`。
- `CrudRouteKey` 由 entity types、operation key 和 scene 组成。
- Engine capability 使用结构化 operation key。
- 治理、审计和幂等读取相同操作语义。
- HTTP 响应使用 operation domain 与 operation，不恢复含义模糊的旧 `op`。

## 关键边界

- Stats 是独立 Domain，不是 Query 的特殊 operation。
- ACTION 必须有 scene，默认 Command Engine 不执行 ACTION。
- Import/Export 是独立 Engine SPI，任务操作不伪装成 Query/Command。
- 外部权限系统需要单字段 action 时，从 operation key 派生，不反向成为内部权威模型。

## 后果

收益是路由、治理、审计和执行能力使用同一类型系统，并能在注册期拒绝非法组合。代价是旧枚举、旧响应字段和字符串 route key 不再兼容。

实施迁移和测试清单已经完成，不在本 Decision 中继续维护。后续新增操作必须同时更新合法矩阵、当前架构和合同测试。
