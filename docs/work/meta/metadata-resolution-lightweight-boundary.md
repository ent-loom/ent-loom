# 元数据裁决轻量实施边界

> 性质：实施边界
> 状态：进行中
> 规范依据：[Metadata Resolution Contract](../../architecture/core/meta/metadata-resolution-contract.md)

> 目标：控制单点实现重量，优先交付运行时收益，同时保留后续模块扩展能力。

## 1. 职责边界
```mermaid
flowchart LR
    C["公共内核<br/>来源 / 优先级 / 合并 / 诊断"]
    M["模块 Core<br/>属性 / 规则 / 运行模型"]
    A["Adapter<br/>属性投影"]
    R["消费者<br/>CRUD / DDL / DOC / UI"]
    C --> M --> R
    C --> A --> M
```
- 公共层负责“如何裁决”，只固定来源、优先级、属性级合并和诊断。
- 模块负责“裁决什么”，持有专属属性、规则、运行模型和消费行为。
- Adapter 只做投影，不实施优先级裁决，不承载业务行为。
- 公共 Resolver 不得依赖模块模型，也不得按模块类型增加分支。

## 2. 效益优先
每个切片只完成“一个规则 -> 一组相关属性 -> 一个可观察效果”。首个闭环为：
```mermaid
flowchart LR
    F["createTime / createdAt"] --> P["CREATED_TIME"]
    P --> O["显式注解逐属性覆盖"]
    O --> E["CRUD 创建自动填充"]
    E --> D["来源可诊断"]
```
禁止更新、默认排序、导出格式分别作为后续切片，不与首个闭环捆绑。

## 3. 抽象准入与停止条件
- 公共抽象必须属于全局不变量，或已有至少两个真实模块共同使用。
- 不因未来可能接入 DDL、DOC、UI 而增加占位 SPI、空实现或泛型层级。
- 新模块应通过新增属性、Convention 或 Adapter 接入，不修改公共裁决算法。
- 若一个切片同时修改裁决算法、Starter 和多个消费者，应立即拆分。
- 新扩展点没有当前调用者、测试或运行时收益时，应推迟实现。

## 4. 固定验收
- [ ] 只有一个主要运行时效果，并有模块测试证明。
- [ ] 公共类型满足准入条件，模块边界未反向依赖；明确本期不做事项及后续启动条件。
> 原则：固定裁决机制，不提前固定模块语义；先验证收益，再提取扩展点。
