# 命令当前实现

> 状态：Current
> 最近核验：2026-08-21
> 范围：`ent-loom-crud`

Command 是 CRUD 的写入能力域，负责默认单表写、批量写、场景命令、幂等和强类型业务 Handler。

## 当前能力

| 能力 | 当前实现 |
|---|---|
| Gateway | `CommandGateway` |
| Spec | `CommandSpec` |
| 操作 | `CREATE`、`UPDATE`、`DELETE`、`SAVE_OR_UPDATE`、`ACTION` 以及显式批量 |
| 路由 | `DefaultCommandRouter` + `SceneHandlerRegistry` |
| 默认引擎 | `RegistryBackedCommandEngine` |
| 幂等 | `IdempotencyManager`，有 idempotencyKey 时包裹执行 |
| 治理 | `governCommand`，写入前完成主体、权限、数据范围和审计 |

## 语义边界

- 默认 Command 面向单表写入。
- 复杂跨表写和业务动作通过 `CommandSceneHandler` 或 `ACTION` 接管。
- 默认引擎不绕过治理和 SQL 安全。
- 强类型 handler 是推荐业务边界，动态 `CrudRecord` 保留在框架入口和低阶 SPI。

详细 Spec、routeKey 和 HTTP 合同见 [Query/Command 协议与路由明细](查询命令协议.md)。

## 必填校验演进边界

[CRUD 外部输入契约与统一校验](../../../evolution/decisions/core/实体必填约束与统一校验.md) 已实施：普通 CRUD 由 `CrudInputContract` 定义创建输入和更新禁改边界，公共校验器按稳定空值语义校验，错误文案按 label 生成。`AbstractEntityCreateHandler` / `CrudCreateHandler`、默认 JDBC CREATE 和 DAO 命令 CREATE 已接入；批量创建通过 CREATE 子命令复用。

默认输入契约校验先于默认值补齐和治理范围注入，显式 `null` 不被默认值覆盖；数据库生成主键由主键策略处理。DOC 运行时使用 `inputRequired` 表达客户端输入提示；实体元数据不再承载 CRUD 输入必填。结构化错误和导入错误定位仍待补齐。
