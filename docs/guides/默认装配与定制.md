# 默认装配与定制

Starter 为重复装配提供配置入口，各能力可独立替换。业务无需复制整个治理配置类。
框架本身不启用演示模式、HTTP 接口或文档暴露策略。

## 本地示例

将以下内容放入 `application-example.yml`，运行时显式激活 `example` Profile。
框架按属性开关启用能力，不依赖约定的 Profile 名称；不要把演示开关放入生产配置。

```yaml
entloom:
  crud:
    example:
      enabled: true
      subject-id: local-developer       # 默认值，可调整
      allow-all-data-scope: true        # 演示模式默认值，可独立关闭
    controller:
      enabled: true
      include-entities: [customer_profile]
    governance:
      permission-rules:
        - resource: customer_profile
          action: '*'
          scene: '*'
          decision: ALLOW
          subject-ids: [local-developer]
  doc:
    contract:
      enabled: true
      http:
        enabled: true
      exposure:
        enabled: true
        subject-ids: [local-developer]
        fields:
          customer_profile: [id, displayName, email]
```

实体仍需通过 Meta 的 `ent.loom.meta.entity-class-names` 或业务 `ResourceCatalogAdapter` 注册。
上述配置使用正式资源编码；文档字段使用 Java 属性名。

## 默认边界

| 能力 | 默认行为 | 定制入口 |
|---|---|---|
| 演示主体 | 演示开关关闭；开启后每次解析创建独立主体 | `subject-id` 或 `CrudSubjectResolver` Bean |
| 演示数据范围 | 开启演示后使用全量范围；关闭全量开关后回到常规治理实现 | `allow-all-data-scope` 或 `CrudDataScopeResolver` Bean |
| HTTP 实体映射 | 从已注册元数据构建映射，按 `include-entities` 限制；空白名单不自动注册 | 白名单或 `ExposedEntityRegistry` Bean |
| 文档暴露 | 策略默认关闭；开启后仅允许所列主体查看所列实体与字段 | 配置或 `EntityDocumentationExposurePolicyResolver` Bean |
| 操作权限 | 继续执行现有权限规则；演示模式不自动放行 | `permission-rules` 或权限服务 Bean |

文档没有通配符约定。缺省主体白名单、缺省字段映射均不公开实体；实体配置空字段集合时只公开实体信息。
新增实体或字段不会自动加入白名单，文档元数据中的 `hidden` 仍优先由公共投影层过滤。
文档暴露不会授予 CRUD 读写权限，HTTP 路由注册也不会跳过操作与场景授权。

## 局部调整

要隐藏 `email`，从 `fields.customer_profile` 中移除它即可。
要更换演示主体，需同时调整 `subject-id`、权限规则和文档主体白名单；它们是独立的授权边界，不互相推导。
配置策略在启动时保存快照，不提供运行期热更新。

## 独立替换 Bean

自动装配使用 `@ConditionalOnMissingBean`，应用声明同类型 Bean 后，只有相应默认实现退让。
以下示意接入应用已有的主体服务：

```java
@Bean
CrudSubjectResolver subjectResolver(CurrentUserService currentUserService) {
    return currentUserService::getSubject;
}
```

`CurrentUserService` 为业务接口，`getSubject()` 返回 `SubjectContext`。
生产应用关闭 `ent.loom.crud.example.enabled`，并接入真实的数据范围实现；缺失适配时保留框架原有的失败关闭行为。

需要按角色动态决定文档字段时，自定义 `EntityDocumentationExposurePolicyResolver`，返回本次请求的完整策略。
自定义策略完整替换配置策略，不与其隐式合并；业务需自行维护主体、实体与字段的访问边界。
自定义 `ExposedEntityRegistry` 同样完整接管路由注册和白名单。
