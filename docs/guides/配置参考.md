# 配置参考

> 状态：Current
> 最近核验：2026-10-27

本文是 Spring Boot 配置的统一入口。`docs-site` 直接展示 `ent-loom/docs`，这里是唯一权威正文；配置前缀、类型和默认值以各模块的 `@ConfigurationProperties` 为准。

## 怎么读

示例工程只展示业务闭环需要的 P1 配置，并允许少量 P2 配置。完整配置项仍在本文按模块列出，不要求业务项目一次性复制。

| 标记 | 含义 | 使用建议 |
|---|---|---|
| P1 | 常见能力的推荐配置，或接入该能力时需要明确的配置 | 按实际启用的能力显式填写 |
| P2 | 默认值通常可用，但特定环境可能需要调整 | 只有改变默认行为时填写 |
| P3 | 专项、兼容或高级配置 | 先确认前置条件，再单独配置 |
| 安全边界 | 与暴露范围、主体或权限有关 | 即使不是 P1，也必须显式确认 |

级别表示“是否推荐填写”，不等于“是否有默认值”。`enabled`、实体来源和 HTTP 暴露范围要结合生效条件理解；安全配置不能因为存在默认值而省略审查。

## 配置归属

当前 Spring Boot 配置项由以下绑定类提供。没有 `@ConfigurationProperties` 的 Core 运行时对象不属于公开 YAML 配置。

| 模块 | 配置前缀 | 绑定类 | 说明 |
|---|---|---|---|
| Meta | `ent.loom.meta` | `EntLoomMetaProperties` | 实体来源、共享默认语义、Meta 到 CRUD / DDL / DOC 的投影和诊断 |
| Meta 文档契约 | `ent.loom.doc.contract` | `EntityDocumentationContractProperties` | 文档契约暴露和 HTTP 入口 |
| CRUD | `ent.loom.crud` | `CrudProperties` | Controller、Query、Command、治理、幂等和导入导出 |
| CRUD 业务访问 | `ent.loom.crud.access` | `CrudProperties.access` → `CrudAccessProperties` | 共享身份、策略与简单关系 |
| CRUD 示例 | `ent.loom.crud.example` | `CrudProperties.example` → `CrudExampleProperties` | 本地演示主体、静态账号、路由和数据范围 |
| DDL | `ent.loom.ddl` | `EntDdlProperties` | 实体来源和执行级别 |

DOC Core 当前没有独立的 Spring Boot 配置类；文档契约适配属于 Meta starter，因此使用 `ent.loom.doc.contract`。

## 配置约定

- 配置键使用小写连字符，例如 `max-file-size`；枚举示例使用 Java 大写常量名，例如 `FIND_ONE`、`CREATE_MODIFY_DELETE_ALL`；布尔开关使用 `enabled: true/false`。
- Java 属性名、资源码、身份码和业务动作码按其定义原样填写，例如 `customerId`，不将它们机械改成连字符。
- Spring Boot 配置保留原生宽松绑定；实体差异使用 Java 注解声明，HTTP 请求协议保持各自合同。
- CRUD 枚举配置省略时使用声明的默认值；显式空字符串或纯空白值启动失败，不回退默认值。
- Meta、文档契约、CRUD、DDL 对已装配的配置前缀严格绑定，未知键启动失败。CRUD 根配置统一绑定 `access`、`example`，子配置 Bean 共享根对象的同一实例。
- 时长和大小使用带单位的值，例如 `retention: 48h`、`max-file-size: 50MB`。旧 `retention-hours`、`max-file-bytes` 已删除；采样率与关系深度等显式越界值直接报错，不静默修正。

时长和大小保留 Boot 原生解析：无单位数字分别表示毫秒和字节，例如 `48` 为 48ms，`50` 为 50B；推荐始终填写单位。幂等保留时长在转换后必须至少为 1s 且为整秒，例如 `1s`、`1000ms`、`48h`；`48`、`1500ms` 均拒绝。此约束与默认 MySQL 幂等表的秒级时间精度一致，过期时间不提供亚秒精度保证。导入导出文件保留时长仍允许毫秒。

集合语义取决于用途，不能仅凭 `[]` 或 `{}` 推断授权：

| 位置 | 省略 | 显式空集合 |
|---|---|---|
| `meta.defaults.created-time-fields` | 使用内置名称 | `[]` 关闭名称推导 |
| `doc.contract.exposure.subject-ids` | 无授权主体 | `[]` 无授权主体 |
| `doc.contract.exposure.include-entities` | 全部 Meta 实体 | `[]` 仍为全部 Meta 实体 |
| `@EntCrudEntity.actions` | 继承策略动作 | `actionsSpecified = true` 且空列表时关闭全部动作 |
| `@EntCrudEntity.operations` | 沿用策略缺省映射 | `create=` 关闭该动作的通用映射 |
| `@EntCrudEntity.ownership` | 使用框架推导 | `ownershipSpecified = true` 且空列表时关闭推导，底层范围约束仍保留 |
| `@EntCrudAccessField.fields` | 由 mode 决定 | `INCLUDE` 拒绝空列表；`EXCLUDE` 不排除候选字段；`ALL/NONE` 允许空列表 |

服务与 HTTP 入口有独立控制价值，例如文档的 `enabled` 与 `http.enabled`；实体的 `http-exposed` 仅控制通用 HTTP。策略授权、服务装配与接口暴露分别生效。

## Meta

### `ent.loom.meta`

| 配置项 | 类型 | 默认值 | 级别 | 说明 |
|---|---|---:|---|---|
| `enabled` | boolean | `true` | P2 | 总开关；关闭后不装配 Meta 适配器 |
| `base-packages` | `list<string>` | `[]`，无显式来源时使用 Boot 自动配置包 | P2 / 实体来源 | 递归扫描包及子包中的 `@EntEntity`、`@EntCrudEntity`、`@EntDocEntity` 具体实体类 |
| `entity-class-names` | `list<string>` | `[]` | P2 / 实体来源 | 精确声明参与投影的实体全限定类名 |
| `crud.enabled` | boolean | `true` | P2 | 是否启用 Meta 到 CRUD 的适配器 |
| `doc.enabled` | boolean | `true` | P2 | 是否启用 Meta 到 DOC 的适配器 |
| `ddl.enabled` | boolean | `true` | P2 | DDL starter 在类路径中时，使用共享 Meta 解析器替代原生 DDL 加载器；自定义 `MetadataLoader` 优先 |
| `defaults.service` | string | `spring.application.name`，应用名缺省时为空 | P2 | 实体未显式声明时的所属服务；显式配置优先于应用名 |
| `defaults.id-policy` | enum `UNSET` / `DATABASE` / `APPLICATION` / `ASSIGNED` | `UNSET` | P1 | 主键值提供方；统一驱动 CRUD 行为与 DDL 映射 |
| `defaults.created-time-fields` | `list<string>` | `createTime, createdAt` | P2 | 全局创建时间命名约定；显式列表整体替换缺省，空列表关闭按名称推导；Meta 与 CRUD 适配共用 |
| `diagnostics.fail-fast` | boolean | `true` | P2 | 元数据诊断发现错误时是否快速失败 |

`base-packages` 支持 Spring 包路径匹配：`*` 匹配一层包，`**` 匹配零层或多层包，例如 `com.example.minicommerce.*.entity`；匹配到的包仍递归扫描子包。

通过 `base-packages` 扫描包，或通过 `entity-class-names` 精确指定实体；两者同时配置时按全限定类名合并去重、排序。均为空时使用 Boot 自动配置包，通常为 `@SpringBootApplication` 所在包；没有 Boot 自动配置包时不注册 CRUD / DOC 适配器，应用可自行提供 `ResourceCatalogAdapter`。显式来源优先，显式包扫描结果为空时不回退。DDL 加载器优先使用 DDL 请求中的显式实体类与包来源；两者均未指定时复用 Meta 实体来源。包扫描只发现实体，不会将实体注册为 Spring Bean；HTTP 暴露仍需单独配置。

实体所属服务优先级：实体显式声明 > `meta.defaults.service` > `spring.application.name`；三者均未提供时保持为空。

主键策略优先级：模块原生显式声明 > Meta 字段显式声明 > 模块全局默认 > Meta 全局默认 > 框架约定。`@EntMetaId(policy = EntIdPolicy.ASSIGNED)` 可声明实体例外；指定应用生成器时推导为 `APPLICATION`，该策略本身不注册生成器。MySQL 当前将 `DATABASE` 映射为单列整数主键的 `AUTO_INCREMENT`。启用 Meta DDL 时，在执行 SQL 前检查已注册 CRUD 实体与 DDL 的表名、主键字段、列名及数据库生成策略；不支持的类型或矛盾覆盖会失败。该检查针对最终模型，不代替已有数据库的结构迁移或校验。

创建时间默认同时识别 `createTime`、`createdAt`，普通实体及公共基类字段无需添加 `@EntMetaDateTime`。项目采用其他命名时，只配置一次：

```yaml
ent:
  loom:
    meta:
      defaults:
        created-time-fields: [recordedAt]
```

此配置对 Meta 扫描的所有实体及继承字段生效。列表整体替换内置命名；项目混用时填写 `[createTime, createdAt, recordedAt]`，配置空列表关闭名称推导。字段还必须为 `LocalDate`、`LocalDateTime`、`Instant` 或 `java.util.Date`，同名文本、数值字段不推导为创建时间。字段名称不得空白、重复或包含首尾空格。实体不必拥有这些字段，缺失时忽略；每个匹配字段都会贡献 `DATETIME.CREATED_TIME`、默认中文名称及只读语义。显式字段元数据和项目 Java 约定继续按现有优先级裁决，配置在装配时冻结。同一实体最终只能有一个 CREATED_TIME 字段；多个角色或关系字段充当创建时间时启动失败，避免依赖字段声明顺序。

CRUD 的 Meta 适配使用同一名称清单，将最终日期角色保留到运行时元数据；创建时间默认禁止普通写入，不会自动填充时间值。普通查询和受授权查询共用默认排序解析器，读取唯一 CREATED_TIME 字段，不再维护另一份时间字段名称清单。SORT 权限仍按可返回且可排序字段推导；默认排序方向与启用入口由 `crud.query.default-sort` 控制。

### `ent.loom.doc.contract`

| 配置项 | 类型 | 默认值 | 级别 | 说明 |
|---|---|---:|---|---|
| `enabled` | boolean | `false` | P1 / 启用文档 HTTP 时必填 | 启用文档契约服务 |
| `exposure.subject-ids` | `set<string>` | `[]` | 安全边界 | 允许访问文档契约的主体；空集合不提供授权主体 |
| `exposure.include-entities` | `set<string>` | `[]` | P2 | 按正式资源编码限定实体；空集合展示全部 Meta 注册实体 |
| `exposure.exclude-entities` | `set<string>` | `[]` | P2 | 排除实体，优先于包含清单 |
| `exposure.fields` | `map<string, set<string>>` | `{}` | P2 | 按正式资源编码限制字段；某实体未配置时展示全部非隐藏字段，显式空集合不展示字段 |
| `http.enabled` | boolean | `false` | P1 | 启用 HTTP 文档契约入口 |

`enabled` 控制文档契约服务，`http.enabled` 控制 HTTP 入口，两者默认关闭。启用契约后，授权主体默认可查看 Meta 注册的全部实体与非隐藏字段；主体白名单为空时不授权。Doc 从 Meta 已注册实体中筛选，不独立扫描包，也不继承 CRUD HTTP 范围。`fields` 只限制字段，不隐式限定实体范围；如只公开指定实体，应配置 `include-entities`。实体范围和字段配置在启动时校验，未知实体编码或字段导致启动失败；文档 `hidden` 仍由公共投影层过滤，不能通过清单放开。

内部文档可复用全量元数据；生产对外契约建议显式配置实体与字段白名单，避免新增元数据自动进入契约。`subject-ids` 不代替认证，生产主体应来自可信认证过程。自定义 `EntityDocumentationExposurePolicyResolver` Bean 可完整替换配置策略及其校验。

## CRUD

### `ent.loom.crud`

以下表覆盖 `CrudProperties` 当前所有公开嵌套字段。集合的空值语义逐项定义；通用 HTTP 是否开放由 Controller 总开关及实体元数据决定，不维护额外 YAML 实体清单。

| `sql-log.pretty` | boolean | `false` | P2 | 是否格式化 SQL 日志 |

#### Controller 与 Query

| 配置项 | 类型 | 默认值 | 级别 | 说明 |
|---|---|---:|---|---|
| `controller.enabled` | boolean | `false` | P1 | 启用框架默认 HTTP Controller |
| `controller.base-path` | string | `/api/ent-crud` | P2 | 默认 CRUD HTTP 基础路径 |
| `controller.default-timezone` | string | `Asia/Shanghai` | P2 | time 参数默认时区 |
| `controller.default-time-field` | string | 空 | P2 | 默认时间字段；空值不自动补充 |
| `controller.default-read-result-mode` | enum `MAP` / `ENTITY` | `MAP` | P2 | 默认读结果模式 |
| `controller.default-null-field-mode` | enum `INCLUDE` / `OMIT` | `OMIT` | P2 | 默认是否保留空字段 |
| `controller.string-filter.default-like-enabled` | boolean | `false` | P2 | 字符串简写是否默认转 LIKE |
| `controller.string-filter.default-like-mode` | enum `CONTAINS` / `PREFIX` / `SUFFIX` / `RAW` | `CONTAINS` | P2 | 默认 LIKE 模式 |
| `controller.string-filter.default-like-exclude-fields` | `set<string>` | `path, fullPath, parentPath, url, uri` | P2 | 不自动套 LIKE 的字段 |
| `query.enabled` | boolean | `true` | P2 | 启用 Query 主链 |
| `query.default-sort.enabled` | boolean | `true` | P2 | 启用默认排序补全 |
| `query.default-sort.apply-to` | `set<enum>` | `PAGE, LIST` | P2 | 生效入口：`PAGE`、`LIST`、`DETAIL`、`FIND_ONE` |
| `query.default-sort.time-direction` | enum `ASC` / `DESC` | `DESC` | P2 | 时间字段排序方向 |
| `query.default-sort.append-id` | boolean | `true` | P2 | 是否追加主键排序保证分页稳定 |
| `query.default-sort.id-direction` | enum `ASC` / `DESC` | `DESC` | P2 | 主键排序方向 |
| `query.default-sort.fallback-to-id` | boolean | `true` | P2 | 没有时间字段时是否回退到主键 |

默认 PAGE/LIST 按运行时元数据中的唯一 CREATED_TIME 字段倒序，再按实际主键倒序；无创建时间或该字段元数据禁止排序时，回退主键。实际字段可以是 createTime、createdAt、recordedAt 等，命名只在 Meta 全局约定中维护；已移除 `query.default-sort.time-fields`。显式排序优先，未包含主键时 SQL 编译器仍追加主键升序保证稳定。关闭默认排序、排除入口或关闭回退只影响业务缺省补全，SQL 编译器的主键稳定排序始终保留。

受授权分页校验调用方排序、服务器默认排序及稳定主键排序的 `SORT` 权限；缺少任一字段能力时在 SQL 前拒绝。排序授权不授予字段返回或筛选权限。普通查询和受授权查询共用同一解析器及配置。

| `dao.pagination.max-page-size` | int | `200` | P2 | 自定义 DAO 单页最大条数 |
| `dao.pagination.max-offset` | long | `1000000` | P2 | 自定义 DAO 最大分页偏移 |

权限规则至少应明确 `resource`、`action`、`scene`、`decision` 和主体范围。生产环境不要依赖示例主体或全量数据范围。

读取可见性不会授予权限。已纳管实体未匹配可信业务入口时拒绝读取；入口识别、配置示例与关联执行边界见[读取可见性](./读取可见性.md)。

### `ent.loom.crud.access`

配置由 `CrudProperties` 一次严格绑定，`access` 子对象承载共享身份、策略和关系；实体注解选择策略并声明字段权限、操作映射和归属差异。通用 HTTP 由 `controller.enabled` 开启，实体可用 `httpExposed = false` 关闭，开放不授予权限。

| 配置项 | 类型 | 缺省 | 级别 | 说明 |
|---|---|---|---|---|
| `identities.<code>.id-field` | string | 身份码 + `Id` | P1 | 简单身份 ID 的业务属性名，不配置 Java 类型名 |
| `identities.<code>.id-type` | enum `STRING/LONG/INTEGER/UUID` | 无，必须显式声明 | P1 | ID 标量值类型，数值要求正整数；类型须匹配引用它的实体关系字段 |
| `policies.<policy>.<branch>.actions` | `list<string>` | `[]`，配置分支时必须非空 | P1 / 安全边界 | 分支为 `public` 或已注册身份码；显式允许的业务动作须在每个绑定实体的操作目录登记 |
| `policies.<policy>.<branch>.scope` | string | 公共分支为 `all`，身份分支为同名关系 | P2 | `all` 不限制归属；其他值引用已登记的简单关系，未知关系拒绝 |
| `relations.<role>.field` | string | 关系名 + `Id` | P1 / 安全边界 | 实体字段；每项至少填写此项或 `identity-field`，空对象不会被 Spring 绑定 |
| `relations.<role>.identity-field` | string | 配置身份的 `id-field`；Java 身份为关系名 + `Id` | P2 | 当前可信身份的已声明 ID 属性，或复杂 Java 快照的标量只读属性 |

实体策略绑定、字段授权、操作映射和归属差异放在[实体注解](#实体注解)。全局 `access` 保留 identities、policies、relations 等共享定义。

## `ent.loom.crud.example`

仅用于示例和本地开发，不能作为生产治理实现。

| 配置项 | 类型 | 默认值 | 级别 | 说明 |
|---|---|---:|---|---|
| `enabled` | boolean | `false` | P2 | 显式开启示例主体和默认数据范围 |
| `subject-id` | string | `local-developer` | P2 | 示例请求主体标识 |
| `allow-all-data-scope` | boolean | `true` | P2 / 本地限定 | 是否为 Gateway 和 DAO 提供全量数据范围；两者可分别通过 Bean 替换，关闭后使用 DAO 需提供 `EntityDaoScopeResolver` |
| `accounts` | `list<Account>` | `[]` | P2 / 本地限定 | 每项包含 `token`、`subject-id`、`identity.code`、`identity.id`；空列表不装配静态 HTTP 认证 |
| `default-access-entry` | string | `default` | P2 | 未命中路由映射时的可信入口 |
| `routes` | `list<Route>` | `[]` | P2 | 每项包含 `path` 和 `entry`；路径不可重复；匹配到不同入口时拒绝；空列表使用默认入口 |

静态账号使用固定结构：`identity.code` 引用 `access.identities` 中已定义的身份码，`identity.id` 先绑定为字符串，再按身份声明的 ID 类型转换并校验。令牌及主体必须唯一；账号与路由缺少必填字段、包含未知字段或路径重复时启动失败。框架在启动时校验声明、类型转换、账号字段及入口身份引用，在准入时再次核验主体类型与归属。入口使用 `@EntAccess(identity = "customer")`，上下文为统一 `AccessContext`，无需业务身份类、泛型类型选择或反射默认推导。

```yaml
ent:
  loom:
    crud:
      example:
        enabled: true
        accounts:
          - token: demo-customer-a
            subject-id: customer-user-a
            identity:
              code: customer
              id: "301"
        default-access-entry: consumer
        routes:
          - path: /api/merchant/**
            entry: merchant
```

此片段需配合已定义的 customer 身份；路由列表只用于服务端入口映射，列表顺序不形成优先级。

所有身份以业务码区分，同一个 `ConfiguredBusinessIdentity` 类可承载多个身份码，快照保存冻结的定义和已转换的不可变标量。身份码、ID 字段和类型分别声明，不因重命名业务类而改变权限。YAML 简单身份可由 `BusinessIdentityRegistration<ConfiguredBusinessIdentity>` 对接真实归属解析器，框架再次检查返回快照的定义及坐标；复杂身份通过 Java 注册并返回自定义不可变快照，与 YAML 策略共用同一授权链。

自定义 `CrudHttpAuthenticationSource` 优先于静态认证。示例模式关闭时不装配静态账号来源，保留的 YAML 身份定义须有可信 Java 解析器，否则启动失败。身份定义本身不授予成员关系或操作权限。身份码和路由入口独立配置，客户端不能指定可信身份或入口。

## DDL

### `ent.loom.ddl`

| 配置项 | 类型 | 默认值 | 级别 | 说明 |
|---|---|---:|---|---|
| `schema` | string | 空 | P1 | 目标数据库 schema；空值使用数据源默认 schema |
| `create-database-if-missing` | boolean | `false` | P2 | 是否允许启动时创建数据库 |
| `mode` | enum `NONE` / `CREATE_TABLE` / `CREATE_TABLE_AND_METAS` / `CREATE_MODIFY_TABLE_AND_METAS` / `CREATE_MODIFY_DELETE_ALL` | `NONE` | P1 | 唯一执行开关：`NONE` 不执行；`CREATE_TABLE*` 只建缺失表；`CREATE_MODIFY_TABLE_AND_METAS` 受控修改；`CREATE_MODIFY_DELETE_ALL` 同步实体表全部差异，允许删除列和重建索引、主键，可能丢失数据；生产环境按迁移策略选择 |
| `base-packages` | `list<string>` | `[]` | P1 / 二选一 | 扫描实体包 |
| `entity-class-names` | `list<string>` | `[]` | P1 / 二选一 | 直接声明实体类名 |
| `defaults.generation-strategy` | enum `UNSET` / `NONE` / `AUTO_INCREMENT` / `IDENTITY` / `SEQUENCE` / `UUID` | `UNSET` | P2 | DDL 专属主键默认；不覆盖 Meta 显式声明，优先于 Meta 全局默认；MySQL 当前支持 `NONE`、`AUTO_INCREMENT`、`IDENTITY` |

`base-packages` 与 `entity-class-names` 是两种实体来源方式；启用 Meta DDL 且未指定 DDL 来源时复用 Meta 实体来源。DDL 包扫描发现 `@EntDdlEntity`；Meta-only 实体可通过 Meta 来源或显式类名加载。实际启用 DDL 时确认实体来源和执行级别。`@EntDdlField(generationStrategy = GenerationStrategy.NONE)` 显式关闭数据库生成；`UNSET` 表示继续使用默认或 Meta 映射。涉及删除或修改的模式应在迁移窗口内使用。

DDL 已移除 `ent.loom.ddl.enabled`，关闭执行请使用 `mode: NONE`；文档已移除 `ent.loom.doc.contract.exposure.enabled`，关闭契约请使用 `contract.enabled: false`，调整公开范围请修改白名单。

## 示例与维护规则

最小业务示例见 [mini-commerce-spring-boot 的配置](../../examples/mini-commerce-spring-boot/src/main/resources/application.yml)；它集中声明实体、CRUD、访问治理与文档能力，按业务场景提供请求演示，无需切换能力 Profile。全量字段参考以本文为准，不额外维护一个长期漂移的 full-demo YAML。

以下规则适用于 Spring Boot 的 `application.yml` 配置；实体注解见文末。

配置维护遵循以下顺序：

1. 在所属模块的 `@ConfigurationProperties` 中新增字段、默认值和中文 Javadoc。
2. 保留 `spring-boot-configuration-processor`，构建时生成 `META-INF/spring-configuration-metadata.json`，让 IDE 能提示配置。
3. 在本文补充路径、默认值、级别、生效条件和安全语义。
4. 更新最小示例只有在业务闭环确实需要该配置时才进行。

条件装配读取的开关也必须在本文出现；未被配置绑定类或条件装配读取的内部字段不作为公开配置。发现源码默认值与本文不一致时，以源码为准并立即修正文档。


## 实体注解

`application.yml` 用于数据源、端口、组件开关、环境身份和项目共享策略等应用配置。实体结构、字段与实体级 CRUD 差异声明在实体类；业务动作入口和能力声明在 Handler 注解；复杂规则由 Java 策略处理。

```java
@EntEntity("订单")
@EntDdlIndex(name = "idx_order_customer", fields = "customerId")
@EntCrudEntity(policy = "workflow", actions = {"view", "create", "cancel"},
    operations = {"create="})
@EntCrudAccess(identity = "customer", addActions = {"create", "cancel"})
class Order { Long id; Long customerId; }
```

- `@EntCrudEntity`：策略选择、HTTP 暴露、动作、归属关系、字段上限和创建/更新输入约束。未声明 CRUD 的实体不会自动发布；`httpExposed = false` 关闭该实体的通用 HTTP。
- `@EntCrudAccess` 与 `@EntCrudAccessField`：按身份声明动作、范围、简单规则及字段用途差异。字段上限声明后，未列出的用途关闭；本次授权只能继续收窄。
- `@EntDdlIndex`：普通索引的 `fields` 使用 Java 持久化属性名，编译为最终数据库列；`expression` 与字段二选一。
- `@EntDocEntity` 和 `@EntDocField`：文档分组、示例、可见性及关系说明；复杂展示差异可提供 `DocOverrideProvider`。
- `@EntCrudCommandAction`：在处理器上声明资源、动作、入口和能力；详见[动作与场景策略](../evolution/decisions/crud/动作注解与场景策略统一声明.md)。

共享身份、关系和策略可由 Java `CrudAccessProperties` Bean 声明，也可使用应用配置；同一项目不能同时使用两种来源。策略还可由 Java `EntityPolicyTemplate` 提供。公共访问必须显式限定范围及返回字段；自定义 Mapper 须自行落实授权结果的数据范围和字段限制。

框架不再加载实体 YAML 文件；实体声明仅通过注解和 Java 扩展点进入运行模型。
