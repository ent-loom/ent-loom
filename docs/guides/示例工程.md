# 示例工程

> 状态：Current

两个示例都是独立 Maven 消费者，不属于 ent-loom 的生产依赖或默认 Maven Reactor。详细配置、启动命令和验收日志以各自仓库 README 为准。

## 选择示例

| 示例 | 定位 | 适合场景 |
|---|---|---|
| [Customer Profile](https://github.com/ent-loom/ent-loom/tree/main/examples/customer-profile-spring-boot) | 最短真实接入闭环 | 第一次启动、理解实体声明、公开 Starter、MySQL 和 HTTP CRUD |
| [Mini Commerce](https://github.com/ent-loom/ent-loom/tree/main/examples/mini-commerce-spring-boot) | 业务扩展示例 | 理解 Handler、事务下单、场景权限、价格快照和失败回滚 |

## 推荐顺序

先完成[快速开始](快速开始.md)并阅读 [Meta 实体建模](meta/index.md)与 [CRUD 数据操作](crud/index.md)，再参考以下完整工程。

1. 先运行 [Customer Profile](https://github.com/ent-loom/ent-loom/tree/main/examples/customer-profile-spring-boot)，完成 `CREATE -> DETAIL`。
2. 再阅读 [Mini Commerce](https://github.com/ent-loom/ent-loom/tree/main/examples/mini-commerce-spring-boot)，观察哪些能力由框架承接，哪些业务规则仍由应用负责。

Mini Commerce 只演示业务扩展边界，不包含登录、租户隔离、支付、库存、消息队列或生产级运维配置，不能直接当作完整商城模板。

## 与内部验收的区别

`ent-loom-tests/ent-loom-e5-static-test` 中也有一个 `CustomerProfile`，它是框架内部的全链路验收 fixture，主要验证 Meta、DDL、CRUD、DOC、UI Runtime Model 以及 H2 + MockMvc。它与上面的公开消费者示例不是同一个工程，详见[实体全链路验收](ddl/实体全链路验收.md)。
