# 读取可见性

用户端只看启用商品、公开文章只看已发布内容，属于服务端数据可见性约束。调用方无需重复传条件，也不能通过修改筛选条件扩大范围。读取条件统一为：

```text
逻辑未删除 AND 租户/组织范围 AND 当前实体可见性 AND 调用方筛选
```

## 声明式配置

配置按「实体资源码 → 可信业务入口 → 字段条件」声明，条件使用实体的 Java 字段名。

```yaml
ent:
  loom:
    crud:
      governance:
        read-visibility:
          product:
            consumer:
              active: true
            management: all
          article:
            public:
              status: [PUBLISHED, ARCHIVED]
```

- 条件支持非空标量等值与非空集合 IN，字段之间取交集。
- 配置值按实体字段类型校验并转换；枚举使用名称，布尔值仅接受 true/false。
- 声明实体后，该实体纳入管理。未匹配到业务入口时拒绝读取，包括将该实体作为关联目标读取。
- Spring Boot 不保留 YAML 空映射入口，请使用 `all`，不要使用 `management: {}`。
- 入口的 `all` 显式表示不追加可见性条件，仍保留原权限和租户、组织范围；省略入口表示拒绝该入口读取。
- 未配置的实体保持既有治理行为。未知实体、字段、非法入口及条件类型错误在启动时失败。
- 当前支持布尔、字符串、枚举和数字字段；日期窗口、当前用户归属等复杂条件应通过业务扩展实现，不能在 YAML 中放 SQL 或表达式。

## 可信入口与权限

`accessEntry` 表示服务端确认的业务入口或访问用途，例如 consumer、management；`portal` 表示 HTTP、SDK 等调用方式。两者不是用户角色。

接入方通过 `AccessEntryResolver` 或可信 `CrudSpecAttributeContributor` 识别业务入口，应依据已验证的身份、受保护路由或服务端固定配置。不要直接信任请求参数或未验证的请求头。内置 HTTP 契约拒绝调用方提交这些保留属性。

权限校验在可见性约束前执行。management 的空条件声明不会授予管理权限，业务权限服务仍需检查主体是否具备管理权限。默认规则型权限服务本身不根据 accessEntry 授权，生产环境应提供相应的权限实现或保护入口。

同一管理员在用户端浏览时仍使用 consumer 规则；在已授权管理入口才使用管理规则。未接入入口识别时默认入口为 base，不会自动识别为 consumer 或 management。

## Java 声明与动态约束

Java 声明和 YAML 共用 `ReadVisibilityContributor`。下面的 Bean 为商品声明两个业务入口：

```java
@Bean
ReadVisibilityContributor productVisibility(EntityMetaRegistry registry) {
    return new ReadVisibilityContributor(
        registry,
        Map.of(Product.class, Map.of(
            "consumer", Map.of("active", true),
            "management", Map.of()
        ))
    );
}
```

需要按当前主体动态收窄时，可以实现 `CrudDataScopeContributor` 并返回实体范围：

```java
return CrudDataScope.allowAll().withReadScopes(Map.of(
    Product.class.getName(),
    CrudReadScope.allow(Map.of("ownerId", currentOwnerId))
));
```

此返回值表示该贡献器不额外限制跨实体公共维度；框架仍将其与已授权范围及其他贡献器取交集。多个来源的拒绝或条件冲突不能被后续贡献器放开。

## 执行边界

内置 JDBC 的列表、分页、详情、单条查询使用同一份实体约束，分页数据和总数一致。EXISTS 子查询、关联展开按目标实体应用其规则；商品 active 不会传播到无该字段的客户或订单明细。关联目标规则不满足时关联返回空集合或空对象；未配置目标入口时拒绝读取。

统计行、总组数、汇总共用约束。导出预览与提交沿用治理后的读取范围，任务快照、持久化和审计保留实体范围。

自定义 RelationLoader 对有约束的目标实体目前明确拒绝执行，避免未经验证的加载器绕过规则。自定义查询引擎和直接使用 DAO/手写 SQL 的 Handler 必须自行落实治理约束，不能仅因为经过 Gateway 就认为已过滤数据。

规则针对当前读取实体生效，不自动改变历史订单中的商品名称和价格快照；下单等写操作仍需独立校验商品状态，读取规则不会替代业务校验。
