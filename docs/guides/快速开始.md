# 快速开始

写一个只有“编号、姓名”的学生实体，通过注解和配置，让框架自动建表、提供创建和查询接口，并输出实体文档。下面从空项目开始，不需要下载示例工程，也无需编写业务 Controller、Service 或 Mapper。

| 能力 | 本页能看到的结果 |
|---|---|
| DDL | 从学生实体生成 MySQL 建表 SQL，并在启动时创建表 |
| CRUD | 通过 HTTP 保存学生、查询学生 |
| DOC | 通过 HTTP 读取“学生／姓名／必填”等实体文档信息 |
| UI | 了解前端接入位置；当前只有 UI 契约，尚无自动生成页面的完整链路 |

## 1. 配置所需能力

准备 **JDK 21、Maven 3.9+、MySQL 8**，新建 Maven 项目 `student-demo`。使用 Spring Boot `3.5.16`、ent-loom `1.0.1`，引入 Web、JDBC、MySQL 驱动及 Meta／CRUD／DDL Starter。

核心配置如下，已包含在后面的完整配置中：

```yaml
entloom:
  ddl:
    enabled: true                         # 启动时执行 DDL，默认关闭
    mode: CREATE_MODIFY_TABLE_AND_METAS    # 创建或修改表结构及元数据
    base-packages: [demo]                  # 扫描带 @EntDdlEntity 的实体

ent:
  loom:
    meta:
      entity-class-names: [demo.Student]   # 注册供 CRUD、DOC 使用的实体
```

省略 DDL 的 `schema` 时使用数据源中的数据库。表名、列名默认转为下划线命名，主键默认识别 `id`；本例创建时手动传入编号。

## 2. 声明学生实体

`src/main/java/demo/Student.java`：

```java
package demo;

import com.entloom.ddl.annotations.EntDdlEntity;
import com.entloom.meta.annotations.EntEntity;
import com.entloom.meta.annotations.EntField;

@EntEntity("学生")
@EntDdlEntity
public class Student {
    @EntField("编号")
    private Long id;

    @EntField("姓名")
    private String name;
}
```

`@EntEntity("学生")` 声明展示名称，实体编码由类名推断为 `student`；`@EntField` 声明字段名称，CRUD 和 DOC 复用这些信息。当前 DDL Starter 扫描仍需要 `@EntDdlEntity`，因此保留这一项。创建请求显式传入编号，不配置数据库自增。

## 3. 配置并启动

在 MySQL 中执行一次 `CREATE DATABASE IF NOT EXISTS student_demo CHARACTER SET utf8mb4;`。设置环境变量 `DEMO_DB_PASSWORD`；连接地址或账号不同，再设置 `DEMO_DB_URL`、`DEMO_DB_USER`。

<details>
<summary>src/main/resources/application.yml（数据源、实体注册、HTTP 与授权）</summary>

```yaml
spring:
  datasource:
    # 默认连接本机 student_demo，可通过环境变量覆盖
    url: ${DEMO_DB_URL:jdbc:mysql://localhost:3306/student_demo?useSSL=false&allowPublicKeyRetrieval=true&serverTimezone=Asia/Shanghai}
    username: ${DEMO_DB_USER:root}  # 数据库账号
    password: ${DEMO_DB_PASSWORD}  # 从环境变量读取密码

ent:
  loom:
    meta:
      entity-class-names: [demo.Student]  # 注册供 CRUD、DOC 使用的实体

entloom:
  ddl:
    enabled: true                         # 启动时执行 DDL，默认关闭
    mode: CREATE_MODIFY_TABLE_AND_METAS    # 创建或修改表结构及元数据
    base-packages: [demo]                  # 扫描带 @EntDdlEntity 的实体
  doc:
    contract:
      enabled: true       # 启用实体文档契约
      exposure:
        enabled: true
        subject-ids: [local-developer]
        fields:
          student: [id, name]  # 未列出的实体和字段不公开
      http:
        enabled: true     # 开放文档 HTTP 接口
  crud:
    example:
      enabled: true  # 仅用于本地演示；真实应用关闭并接入主体和数据范围
    controller:
      enabled: true                 # 开放默认 CRUD 接口
      base-path: /api/ent-crud       # 接口路径前缀
      include-entities: [student]    # 仅开放学生实体
    query:
      enabled: true  # 启用查询
    command:
      enabled: true  # 启用增删改
    import:
      enabled: false  # 本例不启用导入
    export:
      enabled: false  # 本例不启用导出
    sql-log:
      mode: safe  # 使用安全 SQL 日志模式
    governance:
      permission-rules:
        - resource: student  # 授权目标实体
          action: '*'        # 匹配所有操作
          scene: '*'         # 匹配所有场景
          decision: ALLOW    # 允许匹配的请求
          subject-ids: [local-developer]  # 仅限演示主体
      audit:
        persist-to-jdbc: false  # 本例审计不写入数据库
```

</details>

本地演示无需编写治理配置类：`entloom.crud.example.enabled=true` 提供固定主体与全量数据范围；
`controller.include-entities` 自动从元数据注册实体路由；DOC 使用独立的主体和字段白名单。
演示模式不会自动授予操作权限，也不会自动开放 HTTP。

真实应用关闭演示模式，分别提供 `CrudSubjectResolver` 与 `CrudDataScopeResolver` Bean。
每个自定义 Bean 只替换对应默认实现；文档若需要按角色动态判断，可单独提供
`EntityDocumentationExposurePolicyResolver`。详见[默认装配与定制](默认装配与定制.md)。

## 4. DDL：预期产生的 SQL

首次启动、表不存在时，生成并执行的建表 SQL 核心内容如下，无需手动执行：

```sql
CREATE TABLE IF NOT EXISTS `student` (
  `id` bigint NOT NULL,
  `name` varchar(200) NOT NULL,
  PRIMARY KEY (`id`)
);
```

- 表结构未变化：再次启动不重建表、不清空数据。
- 新增字段或索引：当前模式会比较差异，执行受支持的 `ALTER TABLE`；字段修改只支持有限范围，并非任意结构同步。
- 仅需首次建表：将 `mode` 改成 `CREATE_TABLE`。

默认字符串长度为 200，DDL 默认非空；Meta 的 `required = TRUE` 声明业务必填约束，两者独立。可执行 `SHOW CREATE TABLE student;` 核对实际表结构。

## 5. CRUD：创建、查询与组合筛选

提交编号和姓名：

```bash
curl -X POST http://localhost:8080/api/ent-crud/student/create \
  -H 'Content-Type: application/json' \
  -d '{"options":{"requestId":"student-create-1"},"payload":{"id":1001,"name":"张三"}}'
```

创建响应的 `data.id` 是本次传入的编号：

```json
{"success": true, "data": {"rows": 1, "id": 1001}}
```

用返回的编号查询学生：

```bash
curl -X POST http://localhost:8080/api/ent-crud/student/detail \
  -H 'Content-Type: application/json' \
  -d '{"options":{"requestId":"student-detail-1","filterMap":{"id":{"op":"EQ","value":1001}}}}'
```

详情响应的关键内容：

```json
{
  "success": true,
  "data": {"item": {"id": 1001, "name": "张三"}}
}
```

两次响应应成功。数据已写入 MySQL，可以执行 `SELECT id, name FROM student;` 核对。重复创建时请更换编号和 `requestId`。

本例未声明姓名的业务必填约束。如需 CRUD 在创建时校验姓名，可改为 `@EntField(value = "姓名", required = OptionalBoolean.TRUE)`，并导入 `com.entloom.base.common.OptionalBoolean`。

### 组合查询：筛选、排序与分页

查询“姓名包含张”的学生，按编号倒序，每页 10 条，并返回总数：

```bash
curl -X POST http://localhost:8080/api/ent-crud/student/page \
  -H 'Content-Type: application/json' \
  -d '{
    "options": {
      "requestId": "student-page-1",
      "filterMap": {"name": {"op": "LIKE", "value": "张"}},
      "sorts": [{"field": "id", "direction": "DESC"}],
      "page": 1,
      "limit": 10,
      "countMode": "EXACT"
    }
  }'
```

结果应包含刚创建的“张三”；`filterMap`、`sorts`、`page`／`limit` 分别控制筛选、排序和分页，无需新增查询接口。

CRUD 还支持范围过滤、集合匹配、关系展开与统计，详见[常用 CRUD 调用指南](crud/常用CRUD调用指南.md)。

## 6. DOC：读取同一个实体的文档

浏览器打开 [实体文档契约](http://localhost:8080/api/ent-doc/contract)，或执行：

```bash
curl http://localhost:8080/api/ent-doc/contract
```

响应的 `entities` 中包含 `student`（学生），其 `fields` 中的姓名字段如下（节选）：

```json
{"property": "name", "type": "string", "kind": "TEXT", "label": "姓名", "required": false}
```

这个接口提供结构化 JSON 文档，不是 Swagger 页面；字段来自同一份实体声明，并经过上面的文档白名单过滤。
