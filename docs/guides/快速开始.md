# 快速开始

写一个只有“编号、姓名”的学生实体，通过注解和配置，让框架自动建表、提供创建和查询接口，并输出实体文档。下面从空项目开始，不需要下载示例工程，也无需编写业务 Controller、Service 或 Mapper。

| 能力 | 本页能看到的结果 |
|---|---|
| DDL | 从学生实体生成 MySQL 建表 SQL，并在启动时创建表 |
| CRUD | 通过 HTTP 保存学生、查询学生 |
| DOC | 通过 HTTP 读取“学生／姓名／必填”等实体文档信息 |
| UI | 了解前端接入位置；当前只有 UI 契约，尚无自动生成页面的完整链路 |

## 1. 先了解约定，配置所需能力

准备 **JDK 21、Maven 3.9+、MySQL 8**，新建 Maven 项目 `student-demo`。本页使用 Spring Boot `3.5.16`、ent-loom `1.0.1`，引入 Web、JDBC、MySQL 驱动和 Meta／CRUD／DDL 三个 Starter。

| 项目 | 本例采用的约定或配置 |
|---|---|
| 数据库 | 使用数据源 URL 中的 `student_demo`，省略 DDL 的 `schema` |
| 表名、列名 | 默认使用下划线命名，`Student` → `student`、`name` → `name` |
| 主键 | 默认识别 `id`；自增需声明 `AUTO_INCREMENT` |
| DDL 启动执行 | 显式设置 `enabled: true` 和执行模式；默认关闭 |
| 实体发现 | DDL 扫描 `demo` 包；Meta 显式注册 `demo.Student` |

DDL 的核心配置如下，已包含在后面的完整配置中：

```yaml
entloom:
  ddl:
    enabled: true
    mode: CREATE_MODIFY_TABLE_AND_METAS
    base-packages: [demo]
```

当前 DDL Starter 通过 `@EntDdlEntity` 发现实体，尚未自动复用 Meta 实体注册，也不会默认扫描启动类所在包。因此本例保留这项注解和扫描配置，启动执行交给 Starter。

## 2. 声明学生实体

`src/main/java/demo/Student.java`：

```java
package demo;

import com.entloom.base.common.OptionalBoolean;
import com.entloom.ddl.annotations.EntDdlEntity;
import com.entloom.ddl.annotations.EntDdlField;
import com.entloom.ddl.enums.GenerationStrategy;
import com.entloom.meta.annotations.EntEntity;
import com.entloom.meta.annotations.EntField;

@EntEntity("学生")
@EntDdlEntity
public class Student {
    @EntField("编号")
    @EntDdlField(generationStrategy = GenerationStrategy.AUTO_INCREMENT)
    private Long id;

    @EntField(value = "姓名", required = OptionalBoolean.TRUE)
    private String name;
}
```

Meta 注解声明“学生、姓名、必填”等业务含义，CRUD 和 DOC 复用这些信息；DDL 注解启用表发现并指定自增策略。创建学生时只传姓名，数据库生成编号。

## 3. 配置并启动

在 MySQL 中执行一次 `CREATE DATABASE IF NOT EXISTS student_demo CHARACTER SET utf8mb4;`。设置环境变量 `DEMO_DB_PASSWORD`；连接地址或账号不同，再设置 `DEMO_DB_URL`、`DEMO_DB_USER`。

<details>
<summary>src/main/resources/application.yml（数据源、实体注册、HTTP 与授权）</summary>

```yaml
spring:
  datasource:
    url: ${DEMO_DB_URL:jdbc:mysql://localhost:3306/student_demo?useSSL=false&allowPublicKeyRetrieval=true&serverTimezone=Asia/Shanghai}
    username: ${DEMO_DB_USER:root}
    password: ${DEMO_DB_PASSWORD}

ent:
  loom:
    meta:
      entity-class-names:
        - demo.Student

entloom:
  ddl:
    enabled: true
    mode: CREATE_MODIFY_TABLE_AND_METAS
    base-packages: [demo]
  doc:
    contract:
      enabled: true
      http:
        enabled: true
  crud:
    controller:
      enabled: true
      base-path: /api/ent-crud
      include-entities:
        - student
    query:
      enabled: true
    command:
      enabled: true
    import:
      enabled: false
    export:
      enabled: false
    sql-log:
      mode: safe
    governance:
      permission-rules:
        - resource: student
          action: '*'
          scene: '*'
          decision: ALLOW
          subject-ids:
            - local-developer
      audit:
        persist-to-jdbc: false
```

当前 CRUD／DOC 的主体、数据范围与文档白名单仍需 Bean 接入。下面集中提供本地演示配置，业务实体无需编写查询或建表逻辑。

<details>
<summary>src/main/java/demo/DevelopmentGovernanceConfiguration.java（仅本地演示）</summary>

```java
package demo;

import com.entloom.crud.api.model.SubjectContext;
import com.entloom.crud.core.governance.scope.AllowAllCrudDataScopeResolver;
import com.entloom.crud.core.governance.scope.CrudDataScopeResolver;
import com.entloom.crud.core.governance.subject.CrudSubjectResolver;
import com.entloom.crud.core.runtime.meta.EntityMetaRegistry;
import com.entloom.crud.starter.web.registry.ExposedEntityRegistry;
import com.entloom.doc.core.contract.EntityDocumentationExposurePolicy;
import com.entloom.meta.starter.doc.EntityDocumentationExposurePolicyResolver;
import java.util.Set;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

/** 本地演示主体、数据范围与实体文档白名单。 */
@Configuration
public class DevelopmentGovernanceConfiguration {
    @Bean
    CrudSubjectResolver developmentSubjectResolver() {
        SubjectContext subject = new SubjectContext();
        subject.setSubjectId("local-developer");
        return () -> subject;
    }

    @Bean
    CrudDataScopeResolver developmentDataScopeResolver() {
        return new AllowAllCrudDataScopeResolver();
    }

    @Bean
    ExposedEntityRegistry developmentExposedEntityRegistry(EntityMetaRegistry entityMetaRegistry) {
        ExposedEntityRegistry registry = new ExposedEntityRegistry(entityMetaRegistry);
        registry.expose(Student.class);
        return registry;
    }

    @Bean
    EntityDocumentationExposurePolicyResolver developmentEntityDocumentationExposurePolicyResolver() {
        return subject -> {
            boolean subjectAllowed = subject != null && "local-developer".equals(subject.getSubjectId());
            Set<String> exposedFields = Set.of("id", "name");
            return new EntityDocumentationExposurePolicy() {
                @Override
                public boolean isEntityExposed(com.entloom.doc.core.model.DocEntityModel entity) {
                    return subjectAllowed && entity != null && Student.class.equals(entity.entityClass());
                }

                @Override
                public boolean isFieldExposed(
                    com.entloom.doc.core.model.DocEntityModel entity,
                    com.entloom.doc.core.model.DocFieldModel field
                ) {
                    return subjectAllowed && entity != null && Student.class.equals(entity.entityClass())
                        && field != null && exposedFields.contains(field.property());
                }
            };
        };
    }
}
```

</details>

## 4. DDL：预期产生的 SQL

首次启动、表不存在时，生成并执行的建表 SQL 核心内容如下，无需手动执行：

```sql
CREATE TABLE IF NOT EXISTS `student` (
  `id` bigint NOT NULL AUTO_INCREMENT,
  `name` varchar(200) NOT NULL,
  PRIMARY KEY (`id`)
);
```

- 表结构未变化：再次启动不重建表、不清空数据。
- 新增字段或索引：当前模式会比较差异，执行受支持的 `ALTER TABLE`；字段修改只支持有限范围，并非任意结构同步。
- 仅需首次建表：将 `mode` 改成 `CREATE_TABLE`。

默认字符串长度为 200，DDL 默认非空；Meta 的 `required = TRUE` 声明业务必填约束，两者独立。可执行 `SHOW CREATE TABLE student;` 核对实际表结构。

## 5. CRUD：保存并查询学生

只提交姓名，编号由数据库生成：

```bash
curl -X POST http://localhost:8080/api/ent-crud/student/create \
  -H 'Content-Type: application/json' \
  -d '{"options":{"requestId":"student-create-1"},"payload":{"name":"张三"}}'
```

创建响应的 `data.id` 就是自动生成的编号。例如新表首次创建返回：

```json
{"success": true, "data": {"rows": 1, "id": 1}}
```

用返回的编号查询学生（将下面的 `1` 替换为实际 `data.id`）：

```bash
curl -X POST http://localhost:8080/api/ent-crud/student/detail \
  -H 'Content-Type: application/json' \
  -d '{"options":{"requestId":"student-detail-1","filterMap":{"id":{"op":"EQ","value":1}}}}'
```

详情响应的关键内容：

```json
{
  "success": true,
  "data": {"item": {"id": 1, "name": "张三"}}
}
```

两次响应应成功。数据已写入 MySQL，可以执行 `SELECT id, name FROM student;` 核对。重复创建时请更换 `requestId`，无需自行分配编号。

还可以更换 `requestId` 并提交 `"payload": {}`，观察框架返回 HTTP 400、`VALIDATION_ERROR` 和“姓名不能为空”：这就是实体上 `required = TRUE` 在 CRUD 中的实际作用。

## 6. DOC：读取同一个实体的文档

浏览器打开 [实体文档契约](http://localhost:8080/api/ent-doc/contract)，或执行：

```bash
curl http://localhost:8080/api/ent-doc/contract
```

响应的 `entities` 中包含 `student`（学生），其 `fields` 中的姓名字段如下（节选）：

```json
{"property": "name", "type": "string", "kind": "TEXT", "label": "姓名", "required": true}
```

这个接口提供结构化 JSON 文档，不是 Swagger 页面；字段来自同一份实体声明，并经过上面的文档白名单过滤。
