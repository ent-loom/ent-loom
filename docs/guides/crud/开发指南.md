# CRUD 查询、命令与场景

> 状态：Current

本指南旨在帮助开发者快速掌握 `ent-loom-crud` 的使用，包括如何使用实体模型执行查询、提交命令以及如何通过场景（Scene）进行定制。

## 1. 准备实体模型

先按 [Meta：实体建模](../meta/index.md)定义学生实体。`@EntEntity`、`@EntField`、`@EntRelation` 属于 Meta，负责通用业务事实；本页聚焦 CRUD 如何消费实体模型，执行查询、命令与业务场景。

执行 CRUD 还需要运行模块、实体注册、数据源和治理配置；仅添加 Meta 注解不会自动开放接口。完整接入配置见[业务集成模板](业务集成模板.md)，可运行的 Spring Boot 工程见[示例工程](../示例工程.md)。以下片段用于说明各项 API，不是完整应用。

## 2. 查询 DSL (Query Spec)

所有的查询请求最终都会转换为 `QuerySpec`。

### 2.0 标准查询直接使用通用 HTTP

开启 `ent.loom.crud.controller.enabled`、注册实体并绑定访问策略后，普通根实体的 `list/page/findOne/detail` 无需编写业务 Controller。框架从实际内置 Handler 和路由实体解析暴露状态与策略，默认要求有效凭证，通过 `CrudHttpAuthenticationSource` 完成可信准入，复用业务授权执行器处理归属范围、字段用途和审计；新策略资源不再依赖旧主体解析器或演示 grants。

例如商家商品分页：

```http
POST /api/ent-crud/merchantProduct/page
Authorization: Bearer demo-merchant-a
Content-Type: application/json

{"options":{"page":1,"limit":20,"filter":{"active":true}}}
```

客户端只追加业务筛选，身份与归属范围由服务端确定。结果使用 `data.items` 与 `data.page`。此入口支持根实体 `CrudRecord` 和显式授权的本地一级关系投影，配置见[受授权关联读取](受授权关联读取.md)。实体 / DTO 按结果类型推导字段并校验完整授权；查询场景、多实体连接与嵌套展开仍在 SQL 前拒绝；下文其他关系和场景示例属于原有查询能力。

可运行示例见 [mini-commerce](https://github.com/ent-loom/ent-loom/blob/main/examples/mini-commerce-spring-boot/README.md)，后续依赖和验收见[标准查询统一入口实施计划](../../evolution/roadmap/crud/标准查询统一入口实施计划.md)。

### 2.1 过滤条件 (Filters)
支持的操作符：
- `EQ` / `NE`: 等于 / 不等于
- `GT` / `GE` / `LT` / `LE`: 大于 / 大于等于 / 小于 / 小于等于
- `IN` / `NOT_IN`: 包含 / 不包含
- `LIKE`: 模糊匹配（自动处理 `%`）
- `IS_NULL` / `IS_NOT_NULL`: 判空

**JSON 示例**:
```json
{
  "filters": [
    { "field": "name", "op": "LIKE", "value": "张三" },
    { "field": "age", "op": "GE", "value": 18 }
  ]
}
```

### 2.2 排序 (Sorts)
支持 `ASC` 和 `DESC`。
```json
{
  "sorts": [
    { "field": "age", "direction": "DESC" }
  ]
}
```

### 2.3 分页与限制 (Paging)
- `page`: 请求页码（从 1 开始）。
- `limit`: 每页大小。
- `countMode`: `EXACT`（计算总数）或 `NONE`（不计总数，提升性能）。
- `nullFieldMode`: `INCLUDE` 保留记录中的 `null` 字段，`OMIT` 隐藏记录中的 `null` 字段；未传时使用全局默认配置。

### 2.4 关系展开 (Expand Relations)
使用 `expandRelations` 触发 `ROOT_FIRST` 补数逻辑。
```json
{
  "options": {
    "expandRelations": ["class", "orders"]
  }
}
```

## 3. 命令 DSL (Command Spec)

用于数据的增删改。

### 3.1 创建 (CREATE)
`payload` 为实体对象的 Map 表达或 Java 对象。

### 3.2 更新 (UPDATE)
必须包含主键。支持 `dryRun` 试运行模式。

### 3.3 批量操作 (BATCH)
框架支持显式的批量创建和更新，提升性能。

## 4. 场景定制 (SceneHandler)

当默认的 JDBC 引擎无法满足业务需求时（如：需要调用第三方接口、复杂的业务校验），可以注册 `SceneHandler`。

### 4.1 定义 Handler
```java
@Component
public class StudentCustomSceneHandler implements QueryPageSceneHandler {
    @Override
    public CrudRouteKey getRouteKey() {
        return CrudRouteKey.of("student", QueryOperation.PAGE, "custom_scene");
    }

    @Override
    public PageResult<Student> page(QueryExecutionSpec<Student> spec, CrudExecutionContext context) {
        // 1. 执行自定义逻辑
        // 2. 也可以调用默认 Engine 执行基础查询
        return defaultEngine.page(spec, context);
    }
}
```

## 5. 治理扩展

业务系统通常需要实现以下接口来接入自己的账号和权限体系：

- **`CrudSubjectResolver`**: 从请求中提取当前用户、租户 ID。
- **`CrudPermissionService`**: 实现自己的权限判定逻辑。
- **`CrudDataScopeResolver`**: 定义数据权限（如：只能看自己创建的数据）。

## 6. 响应结构

框架返回统一的 `CrudResponse`：

```json
{
  "success": true,
  "code": "OK",
  "data": {
    "items": [...],
    "page": {
      "total": 100,
      "page": 1,
      "limit": 20
    }
  },
  "requestId": "..."
}
```
普通 Java 查询优先返回实体或明确 DTO，类型化入口按结果属性检查完整字段授权；动态 `CrudRecord` 只携带实际授权投影。不要将字段未授权等同于赋 null 脱敏。详见[实体优先的类型化 CRUD](实体优先的类型化CRUD.md)。
