# 双端分页入口与范围

> 状态：Current；订单标准读取及一级关联已迁移到通用 CRUD，无业务查询 Controller。
> 示例：[Mini Commerce](../示例工程.md)；验收用例：[CommerceOrderPageIntegrationTest](../../../examples/mini-commerce-spring-boot/src/test/java/com/example/minicommerce/order/CommerceOrderPageIntegrationTest.java)。

客户与商家查询同一个 `commerceOrder` 资源，使用相同 `list/page/findOne/detail` 入口。框架从可信认证取得当前身份，客户按 `customerId` 限定，商家按 `merchantId` 限定；客户端筛选与授权范围取交集，数据与 count SQL 使用相同条件。

## 实体与声明

[CommerceOrder](../../../examples/mini-commerce-spring-boot/src/main/java/com/example/minicommerce/order/entity/CommerceOrder.java) 每笔属于一个客户和一个商家，跨商家结算在事务内生成多笔订单。实体通过 `@EntCrudGrant` 声明操作资格与字段差异，`application.yml` 的 `grant-defaults` 提供默认身份归属约定。

`view` 缺省映射 `LIST/PAGE/FIND_ONE/DETAIL`。框架按当前可信身份与默认归属约定构造范围，实体注解声明静态上限和身份字段差异。

| 当前身份 | 固定范围 | 允许追加的归属筛选 |
| --- | --- | --- |
| 客户 | `customerId = 当前客户` | `merchantId` |
| 商家 | `merchantId = 当前商家` | `customerId` |

两端还允许按订单 ID、金额、状态、创建时间筛选；排序省略白名单时复用可返回且元数据允许排序的普通字段。不传排序时按统一 CREATED_TIME 角色默认倒序，再按实际主键倒序；无创建时间时回退主键。请求体和自定义身份 Header 不能切换当前身份；客户端按归属字段筛选仍与可信范围取交集，指定其他归属时返回空集合。

## 请求与响应

先启动示例，再执行 [order-query-demo.sql](../../../examples/mini-commerce-spring-boot/scripts/order-query-demo.sql)。完整请求见 [order-query.http](../../../examples/mini-commerce-spring-boot/requests/order-query.http)。

```http
POST /api/ent-crud/commerceOrder/page
Authorization: Bearer demo-customer-a
Content-Type: application/json

{"options":{"filter":{"merchantId":1001},"page":1,"limit":20}}
```

返回订单 501、504，`data.page.total=2`。换成商家甲令牌并按 `customerId=301` 筛选也返回这两笔订单，但两次身份授权独立执行。

| 令牌 | 身份 | 不追加筛选的订单 ID |
| --- | --- | --- |
| `demo-customer-a` | 客户 301 | 501、502、504 |
| `demo-customer-b` | 客户 302 | 503、505 |
| `demo-merchant-a` | 商家 1001 | 501、503、504 |
| `demo-merchant-b` | 商家 2001 | 502、505 |

分页缺省每页 20 条，响应为 `data.items`、`data.page`（含 page、limit、total、totalKnown）。传 `countMode: NONE` 不查总数，返回 `hasNext`。列表响应为 `data.items`，单条响应为 `data.item`，空字段是否保留由 `nullFieldMode` 决定。

旧 `/api/consumer/orders/page` 和 `/api/merchant/orders/page` 已删除，不保留平行查询协议。

## 关系详情

```http
POST /api/ent-crud/commerceOrder/detail
Authorization: Bearer demo-merchant-a
Content-Type: application/json

{"id":501,"options":{"expandRelations":["customer","orderItemList"]}}
```

先授权订单，再按已返回订单的连接键批量读取关联。商城声明式授权沿用关联逐字段投影，商城包含客户邮箱；需要限制时在实体授权注解或实体动态扩展中收窄父资源的 `EXPAND` 字段能力。明细只属于当前授权订单，独立 HTTP 保持关闭。详情和分页都可按请求显式展开，一对多不会改变订单分页与总数。投影和规模边界见[受授权关联读取](受授权关联读取.md)。

跨归属 `detail` 返回 404，`findOne` 返回空；缺少或无效凭证返回 403。实体/DTO 输出、查询场景、多实体连接与嵌套展开仍明确拒绝。

## 下单边界

下单和取消使用同一 Java 授权链。下单的客户 ID 来自可信身份，订单编排服务在事务中拆分跨商家订单；取消的归属与原状态同时进入 UPDATE。通用订单创建映射关闭，通用更新和删除未开放。原始 Mapper 的约束由业务落实，不能绕过授权结果。

## 验证

用 JDK 21 在示例目录执行 `../../mvnw clean test`。测试覆盖四个账号的分页与计数、筛选交集、稳定排序、列表/详情、关系字段差异、跨归属拒绝、伪造 Header、无计数分页及下单事务回归。

真实数据库复用相同用例，执行方法见[MySQL 8 验收](https://github.com/ent-loom/ent-loom/blob/main/examples/mini-commerce-spring-boot/docs/mysql-acceptance.md)。
