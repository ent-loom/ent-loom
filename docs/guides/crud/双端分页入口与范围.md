# 双端分页入口与范围

> 状态：Current；订单标准读取及一级关联已迁移到通用 CRUD，无业务查询 Controller。
> 示例：[Mini Commerce](../示例工程.md)；验收用例：[OrderPageIntegrationTest](../../../examples/mini-commerce-spring-boot/src/test/java/com/example/minicommerce/order/OrderPageIntegrationTest.java)。

客户与商家查询同一个 `order` 资源，使用相同 `list/page/findOne/detail` 入口。框架从可信认证取得当前身份，客户按 `customerId` 限定，商家按 `merchantId` 限定；客户端筛选与授权范围取交集，数据与 count SQL 使用相同条件。

## 实体与声明

[Order](../../../examples/mini-commerce-spring-boot/src/main/java/com/example/minicommerce/order/entity/Order.java) 每笔属于一个客户和一个商家，跨商家结算在事务内生成多笔订单。实体在 `ent/entities/order.yml` 中通过 `crud.policy: order-read` 选择全局读取策略，Java 保留客户与商家归属字段。主配置声明：

```yaml
policies:
  order-read:
    customer:
      actions: [view]
    merchant:
      actions: [view]
```

`view` 缺省映射 `LIST/PAGE/FIND_ONE/DETAIL`。关系范围由身份同名关系推导，字段差异由 `ent/entities/order.yml` 的 `crud.fields` 声明；示例无需查询 Service 或手动构建授权执行器。

| 当前身份 | 固定范围 | 允许追加的归属筛选 |
| --- | --- | --- |
| 客户 | `customerId = 当前客户` | `merchantId` |
| 商家 | `merchantId = 当前商家` | `customerId` |

两端还允许按订单 ID、状态、创建时间筛选；排序省略白名单时复用可返回且元数据允许排序的普通字段。不传排序时按统一 CREATED_TIME 角色默认倒序，再按实际主键倒序；无创建时间时回退主键。请求体和自定义身份 Header 不能切换当前身份；客户端按自身归属字段筛选返回 403。

## 请求与响应

先启动示例，再执行 [order-query-demo.sql](../../../examples/mini-commerce-spring-boot/scripts/order-query-demo.sql)。完整请求见 [order-query.http](../../../examples/mini-commerce-spring-boot/requests/order-query.http)。

```http
POST /api/ent-crud/order/page
Authorization: Bearer demo-customer-a
Content-Type: application/json

{"options":{"filter":{"merchantId":1001},"page":1,"limit":20}}
```

返回订单 501、504，`data.page.total=2`。换成商家甲令牌并按 `customerId=301` 筛选也返回这两笔订单，但两次身份授权独立执行。

| 令牌 | 身份 | 不追加筛选的订单 ID |
| --- | --- | --- |
| `demo-customer-a` | 客户 301 | 501、502、504 |
| `demo-customer-b` | 客户 302 | 503、505 |
| `demo-merchant-a` | 商家 1001 | 501、503、504 |
| `demo-merchant-b` | 商家 2001 | 502、505 |

分页缺省每页 10 条，响应为 `data.items`、`data.page`（含 page、limit、total、totalKnown）。传 `countMode: NONE` 不查总数，返回 `hasNext`。列表响应为 `data.items`，单条响应为 `data.item`，空字段是否保留由 `nullFieldMode` 决定。

旧 `/api/consumer/orders/page` 和 `/api/merchant/orders/page` 已删除，不保留平行查询协议。

## 关系详情

```http
POST /api/ent-crud/order/detail
Authorization: Bearer demo-merchant-a
Content-Type: application/json

{"options":{"filter":{"id":501},"expandRelations":["customer","orderItemList"]}}
```

先授权订单，再按已返回订单的连接键批量读取关联。商家只能看到客户 ID 和名称，客户可查看本人邮箱；明细只属于当前授权订单。明细独立 HTTP 保持关闭。一级关系和字段通过 `EXPAND` 显式授予，详情和分页都可使用；一对多不会改变订单分页与总数。投影和规模边界见[受授权关联读取](受授权关联读取.md)。

跨归属 `detail` 返回 404，`findOne` 返回空；缺少或无效凭证返回 403。实体/DTO 输出、查询场景、多实体连接与嵌套展开仍明确拒绝。

## 下单边界

订单 `place` 仍使用实体显式声明的入口、能力和主体场景授权，执行 Handler 后统一审计，业务事务保留跨商家拆单、快照与失败回滚。它按声明分流，不是新授权失败后的回退；可信作用域禁止降级。

当前演示下单尚未迁入可信客户聚合创建授权，`customerId` 仍是演示结算对象。标准读取不使用该演示权限；旧 `local-developer` 主体不能无 Token 读取订单。普通订单创建、修改和删除继续拒绝。

## 验证

用 JDK 21 在示例目录执行 `../../mvnw clean test`。测试覆盖四个账号的分页与计数、筛选交集、稳定排序、列表/详情、关系字段差异、跨归属拒绝、伪造 Header、无计数分页及下单事务回归。

真实数据库复用相同用例，执行方法见[MySQL 8 验收](https://github.com/ent-loom/ent-loom/blob/main/examples/mini-commerce-spring-boot/docs/mysql-acceptance.md)。
