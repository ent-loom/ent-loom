# 受授权关联读取

绑定实体访问策略后，通用 `list/page/findOne/detail` 可通过 `options.expandRelations` 展开已经声明的本地一级关系，输出为 `CrudRecord`。实体/DTO 输出、查询场景、多实体连接、关系筛选、嵌套及远程关联仍明确拒绝。

## 字段授权

根记录沿用 `RETURN/FILTER/SORT`；关联使用同一身份字段方案的 `EXPAND`。例如：

```yaml
# ent/entities/order.yml
crud:
  policy: order-read
  fields:
    merchant:
      EXPAND: {mode: EXCLUDE, fields: [customer.email]}
```

文件按实体资源码声明，默认 EXCLUDE：本例允许普通关联字段，但排除客户邮箱。`关系.字段` 只允许目标实体的普通持久化字段，拼错路径启动失败。EXCLUDE 会展开已知关系的字段路径，确保整段关系授权不能绕过子字段排除；排除裸关系名（如 `customer`）则关闭整段关系。空排除列表允许全部候选关联字段；新增字段会自动开放，需要固定投影时可使用 `mode: INCLUDE` 和显式字段路径。

未声明 EXPAND 不授予关联读取；展开权限不授予根实体过滤、排序或独立访问目标实体的权限。

这里的 `EXPAND` 是**父资源操作授予的关系读取能力**：在本次根实体授权范围内，按元数据连接键读取指定关联字段，不继承目标实体的独立 HTTP 权限，也不向调用方授予目标实体的全局读取能力。需要目标资源另行授权的关系应由专门业务能力承接，不将其配置为父资源可直接展开的关系。

## 请求与执行

```http
POST /api/ent-crud/order/detail
Authorization: Bearer demo-merchant-a
Content-Type: application/json

{"options":{"filter":{"id":501},"expandRelations":["customer","orderItemList"]}}
```

执行顺序：

1. 按当前可信身份授权根实体操作、范围和字段；校验全部关系及其投影后才执行 SQL。
2. 先查根记录，分页与 count 使用相同范围。一对多关联不会放大根记录数量。
3. 从实际返回的根记录提取连接键，按每批 200 个键加载关联，复用 JDBC 编译器、逻辑删除和 SQL 安全守卫。无计数分页只为本页实际返回的记录补数。
4. 仅输出授权字段；内部连接键不因加载关联自动进入响应。单值关联没有记录返回 null，集合关联返回空列表。
5. 一次操作在关联补数与投影全部成功后记录成功审计；任一环节失败则整个请求失败。

每个关系在单次请求中最多加载 1000 条记录，超限明确报错，不返回被截断的明细。单值关系出现多条记录也会报错。独立关闭 `OrderItem` HTTP 暴露不会阻止已授权的订单明细展开。

Java 项目自行创建策略注册表时，使用接收 `EntityMetaRegistry` 的构造器，以便从同一关系图编译 `EXPAND` 字段路径；仅传实体集合的构造器不编译关系字段路径。
